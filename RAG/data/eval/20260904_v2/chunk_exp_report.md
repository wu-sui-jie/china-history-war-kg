## 四、结论

**判定：保持 800/80（不切换切分参数）。** 依据（离线、确定性、同一题库与配置）：

1. **最直接的检索质量指标在基线最好**：文本 top-k 召回 94.6%（500/100 为 93.2%、1200/120 为 92.9%）；
   dual 配置的融合文本携带也是基线/1200 最高（86.3%），500/100 降至 84.2%。
2. **回答覆盖没有一致优势**：dual 下基线最高（67.6% 对 66.4%/67.6%），text-only 下 500/100 与 1200/120 略高
   （73.5% 对 71.7%），方向相反、量级 1.2–2.1 个百分点，不足以支撑换参。
3. **500/100 的成本明确上行**：片段 +22%（9,544 → 11,641）、向量化请求 955 → 约 1,165 次、
   向量体积 +22%、索引目录 54 MB → 60 MB；而收益只在"引用携带(文本)"一项为正（+4.8 / +8.3 个百分点）。
4. **1200/120 是用检索质量换成本**：省 8.4% 片段（955 → 874 次请求、54 → 53 MB），但文本召回 −1.7 个百分点，
   不划算。
5. **换参的隐性代价**：`chunk_id` 全量变化 → v4 基线 `run_20260913_postaudit` 失去可比性，全部对照需重跑。

**保留的观察（供 v5 后续复测，不作为本次换参依据）**：

- 500/100 的"引用携带(文本)"显著更高（dual 68.5% 对 63.7%；text-only 75.0% 对 66.7%）：更碎的片段让
  回答引用里更容易命中标注词，但没有转化为回答覆盖或 ok 数（均 28/28，dual 覆盖反而略降）。
  引用携带是"证据里出现标注词"的机械指标，正确性仍以人工评分为准（v4 基线 0 correct / 23 partial / 16 incorrect）。
- 片段边界质量随窗口放宽而改善：以句末标点结尾的比例 84.7% → 86.3% → 87.5%（500/100 → 800/80 → 1200/120），
  但未转化为检索指标。
- 建议：v5 向量通道接入后，用 `vector` / `hybrid` 配置对 500/100 与 800/80 复测一次——向量按语义召回，
  对片段粒度可能比 BM25 更敏感——再决定是否切换。
