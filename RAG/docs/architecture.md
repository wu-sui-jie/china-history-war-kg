# RAG 问答系统总体架构

- 文档类型：总体架构
- 状态：生效（已按在线链路实现核对）
- 创建时间：2026-09-03
- 最近核验：2026-09-15
- 适用数据版本：`RAG_ACTIVE_VERSION`（未配置时取最新一致版本）

## 文档目的

本文档记录 RAG 问答系统的总体技术形态、目录结构、数据流、请求流、运行环境和非功能性要求。具体功能仍以 features 下功能文档为准。

## 数据规模参考

旧项目当前实测数据量如下：

1. 事件约 1050。
2. 地点约 5316。
3. 人物约 2492。
4. 组织约 1067。
5. 关系约 17700。
6. 主要原始战争史文本约 30 万字。

该规模用于判断 F03 内存图谱和 F11 索引选型，不承诺数据治理后数量不变。

## 技术选型

以下为建议方案，实际以开发时最终确认版本为准。

1. 后端：FastAPI + Uvicorn。
2. 图谱存储：RAG 内部只读数据快照，不使用旧 Neo4j。
3. 文本索引：关键词索引 + 云端向量索引。
4. 大模型：`deepseek/deepseek-v4.1-flash`（中转 id；官方口径 `deepseek-flash`），通过 OpenAI 兼容接口调用。
5. 前端：Vue 3 + TypeScript + Vite，图谱使用前端图表库。
6. 会话与状态：页面本地保存会话历史，后端按请求携带上下文，不实现账号体系。

## 目录结构

```text
RAG/
├── docs/               # 总览、架构、数据契约与功能文档
├── data/
│   ├── snapshot/       # F09 治理后快照
│   └── index/          # F11 构建的文本与向量索引
├── contracts/          # 统一数据契约的 Python 实现（证据/SSE/panel/请求等）
├── config/             # 默认值（defaults.py）与 .env/环境变量加载（settings.py）
├── evaluation/         # F10 评测包（题库/链式复跑/指标/报告/评分）
├── lib/                # 通用工具（JSON 读写、日志、版本号）
├── server/
│   ├── query/          # F02 问题理解与改写
│   ├── graph/          # F03 图谱检索
│   ├── text/           # F04 文本检索
│   ├── fusion/         # F05 证据融合
│   └── generate/       # F06 回答生成
├── frontend/
└── scripts/
```

## 数据流

```text
旧项目数据（只读）
    ↓
F09 导出快照、实体消歧、孤立节点处理、人工抽检
    ↓
快照分为两条：
    ├→ F03 使用的干净图谱快照
    └→ F11 文本切分与索引构建
            ↓
      关键词索引 + 云端向量索引
            ↓
      F04 文本检索
```

F09 每次重跑都生成新版本号和索引清单，避免 F11 旧索引与 F09 新快照错位。

## 请求流

```text
用户问题
    ↓
F01 前端发起请求（问题 + 会话历史 + 筛选条件）
    ↓
F02 问题类型判定、实体识别、多轮指代消解、查询改写
    ↓
F03 图谱检索  +  F04 文本检索
    ↓
F05 证据融合、排序、去重、分配引用编号
    ↓
F06 生成带引用回答，通过 SSE 推送过程事件与答案
    ↓
F07 展示答案、证据、图谱、时间线、地图
```

F02 属于请求流入口，不消费 F09 输出；F09 和 F11 属于离线数据流，两者不要混读。

## 统一接口与契约

1. F03、F04、F05、F06 的证据格式使用统一数据契约。
2. 证据契约见 data-contract.md。
3. F01 与 F06 的流式事件协议也在 data-contract.md 中定义。
4. 任何字段调整都需要同步更新 data-contract.md 和对应功能文档。

## 环境变量清单

代码中不硬编码密钥，统一通过环境变量或 .env 提供。

1. 向量模型接口地址与密钥。
2. 生成模型（默认 `deepseek/deepseek-v4.1-flash`）接口地址、密钥和模型名。
3. 备用生成模型接口与模型名。
4. 缓存目录、索引目录、快照目录。
5. 限流参数。
6. 检索与拒答阈值（`TEXT_MODE` / `TEXT_HYBRID_STRATEGY` / `VECTOR_REFUSAL_MIN_SCORE`）。

（F08 示例区无演示模式开关，恒显示，不占环境变量。）

## 运行与部署

1. RAG 可独立启动，不依赖旧 backend、frontend、Neo4j。
2. 本地开发分别启动 RAG 后端与 RAG 前端。
3. 在线演示使用独立域名或路径发布，接口与前端同源或配置跨域。
4. 无登录公开页面必须配置基础限流，防止接口被高频调用刷穿。

## 非功能性要求

1. 演示环境网络正常时，目标首 Token 不超过 5 秒，单轮总时间不超过 30 秒。
2. 实际延迟在 F10 评测阶段记录，目标值可随实测结果调整。
3. 关键词检索、图谱检索不依赖云端模型，可在网络异常时保留部分能力。
4. 回答生成需要超时、重试和备用模型降级，不能单点依赖一个模型服务。
5. 相同问题建议命中缓存，降低演示延迟和 API 成本。
6. 页面需兼容桌面演示，并尽可能适配移动端。
7. F02 在词典未命中时需要调用大模型做实体识别、改写和类型判定，F06 再调用生成模型，两次串行调用会占用首 Token 预算。
8. F02 的大模型结果需要缓存，避免相同问题重复支付串行调用成本；首 Token 目标应在该场景下单独实测。

## 风险记录

1. 原始图书文本用于切分建库时，需要确认数据授权。
2. 历史地点坐标覆盖率不足时，地图模块会降级为地点列表。
3. 时间缺失或表述模糊时，时间线模块需要设计降级展示。
4. 问题类型分类和检索阈值最终以 F10 评测为准。
5. F02 大模型串行调用会影响首 Token，需要缓存和现场实测。
