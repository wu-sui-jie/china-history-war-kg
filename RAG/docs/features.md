## 一、F01 智能问答主界面

### 功能作用

整个 RAG 问答页面的核心入口：输入历史战争相关问题，看到完整问答结果与检索过程。
F07 知识面板、F02 实体识别结果、检索过程与引用证据都呈现在**同一个页面**内，不拆多个页面。

### 用户场景

1. 打开页面直接进入问答界面，不需要先读项目介绍。
2. 连续追问同一场战争、同一人物或同一地点。
3. 查看答案来源、图谱子图、时间线和地图信息。
4. 页面内保留本次会话的历史问答记录，可点任意一轮回到该轮的完整回答与知识面板。
5. 开多个会话（新建/切换/重命名/删除），每会话独立保存问答记录；
   左侧按"会话列表 → 该会话的轮次列表"两级展示。
6. 把当前会话导出为 Markdown（回答正文 + 引用来源清单），用于归档或分享。
7. 选择朝代、战争类型等筛选条件后提问。

### 输入与输出

- 输入：问题文本、会话 ID、会话历史、朝代/战争类型筛选条件、纠正后的实体、页面操作。
- 输出：流式回答、过程事件、引用列表、实体识别结果、知识面板数据、错误提示。

### 实现口径

1. 独立前端页面，不与旧前端共享页面代码。
2. 结构为左侧提问历史栏（可折叠）、中间对话区、右侧知识面板区；窄屏下两侧改为抽屉。
3. 问答请求发到 RAG 后端，由后端完成实体识别、双通道检索与回答生成。
4. 流式输出，展示"正在识别实体、正在检索图谱、正在检索文本、正在生成回答"等过程。
5. 基础操作：新建会话、导出会话（Markdown）、复制回答、展开引用。
6. 会话历史保存在浏览器本地，刷新后仍在；多轮追问时把近期历史随请求发送给后端。
   左侧提问历史栏列出每一轮（含失败/取消/被重查取代的轮次，带状态徽标），
   点击即把知识面板切到该轮并滚动定位到聊天区对应消息；新提问自动回到最新视图。
7. 多会话：会话列表在轮次列表之上（可折叠），支持新建/切换/重命名/删除；
   会话标题按首条提问的前 15 字自动生成、可改名。会话数据保存在浏览器本地
   （`schemaVersion 3`，旧版本数据自动迁移或隔离），会话数与每会话消息数均有上限，
   超限按最近使用裁剪。存储键按账号分桶（`ragv5-session-v3:u{uid}`），见
   [current-status.md](current-status.md) 第一节。
8. 会话级导出：导出当前会话为 Markdown，含轮次时间、问题、回答正文与
   **引用编号到来源的对照清单**——正文里的 `[n]` 脱离界面后仍可溯源。
9. 筛选入口提供朝代、战争类型，筛选条件**同时传给图谱检索和文本检索**，不只注入提示词。
10. 请求与 SSE 事件字段遵循 [data-contract.md](data-contract.md)。

### 边界与不变量

1. 页面打开后无需登录即可提问，不依赖 F08 示例区。
2. 用户纠正实体后发起**新**的问答请求，不修改已结束的历史回答。
3. 被纠正或重试取代的轮次由 `supersededBy` 标记，不进下一轮历史（见 data-contract）。
4. 只有 `normal` / `refused` / `degraded` 可作为多轮历史上下文；
   `cancelled` / `failed` / `interrupted` 一律排除。

### 依赖与前置条件

RAG 后端服务可启动；检索索引已构建；大模型服务配置可用。

### 验收标准

1. 页面打开后无需登录即可提问。
2. 提问后可以展示带引用的回答，关键检索步骤对使用者可见。
3. 页面不出现旧版后台的菜单、模板内容或无关文案。
4. 筛选条件同时影响图谱检索和文本检索结果。
5. 提问历史可点回任意一轮：知识面板恢复该轮的引用证据、实体卡、图谱子图、时间线与地点数据，
   并明确提示当前不在最新一轮（可一键返回最新）。
6. 新建/切换/删除/重命名会话后刷新页面，会话列表与当前会话保持；
   旧格式本地数据能自动迁移或隔离，且不出现报错。
7. 任意一段会话可导出为 .md 且 Markdown 渲染正常，正文引用编号能与来源清单逐条对应。

## 二、F02 问题理解、实体识别与消歧

### 功能作用

从用户问题中判定问题类型、识别事件/人物/组织/地点/朝代实体、处理多轮追问的指代问题，
并把别名与古今地名归一到知识库标准实体，保证后续图谱检索与文本检索能够命中。

### 输入与输出

- 输入：问题文本、会话历史、筛选条件。
- 输出：问题类型、改写后问题、最终实体列表、候选实体列表、实体类型、
  归一化后的标准名称、朝代软偏置、置信度。

### 实现口径

1. 建立事件名、人物名、组织名、地点名、朝代名词典；优先用词典与规则快速匹配
   （如"XXX之战"识别为事件）。
2. 词典无法覆盖时才调用大模型做实体识别——`ENABLE_LLM_ENTITY_FALLBACK` **默认关闭**，
   `llm_entity_used` 字段上报本次实体是否来自 LLM 兜底。
3. 别名表与古今地名映射把"涿鹿之野""涿鹿县"归一到标准实体。
4. 实体识别结果同时提供给图谱检索通道与文本检索通道。
5. 问题类型按句式、实体数量与关系词判定（见下），作为公共参数传给 F03/F04/F05。
6. 多轮追问时结合会话历史做指代消解，把"它""他""这场战争"替换成完整实体名，
   输出改写后问题供 F03/F04 使用，避免口语表达导致检索失败。
7. 同名歧义降级：同一 mention 有多个候选时，`candidates` 随 `entities` 一起输出，
   供前端实体卡展示与手动纠正；没有歧义时可为空。
8. 跨朝代同名事件按**问句里提到的朝代**做偏好消歧（如问"西汉的井陉之战"命中西汉那条），
   `dynasty_disambiguated` 字段上报是否发生。
9. `rewritten_question` 是后端内部路由字段，由 F02 生成，前端首轮不传。

### 问题类型分类

| 取值 | 含义 |
| --- | --- |
| `single_entity` | 介绍单个实体 |
| `relation` | 查询关系或参与方 |
| `event_event` | 查询事件之间的关系 |
| `comparison` | 比较多个实体或事件 |
| `timeline` | 查询时间顺序或时间线 |
| `background` | 查询过程、原因、背景 |
| `unknown` | 无法判定 |

### 筛选条件：硬过滤与软偏置

**这是本功能最容易改错的地方，两种机制必须分开看。**

- **显式筛选（硬过滤）**：只有 F01 下拉传来的 `filters` 会真正过滤结果。
- **问句自动识别（软偏置）**：F02 还会从问句识别朝代（如"战国时期的长平之战"→`战国`；
  "鸣条之战与商朝的建立有什么关系"→`商`，含单字朝代 + 朝/国/代 后缀），
  但只写入 `F02Output.dynasty_bias`，**不剔除任何结果**。偏置的实际生效范围：
  - **图谱侧生效**：F03 在策略执行前重排命中节点，可经 `top_k` 截断影响证据集合；
  - **文本侧不生效（如实说明）**：F04 只是把命中朝代的片段前置在"检索返回序"里，
    随后 F05 按相关分（min-max 归一化、分各不同）重排，返回序被覆盖；即文本侧偏置
    目前不改变最终排序。若未来需要文本侧生效，可把偏置折进文本 `_score`
    （会改变融合排序，需重跑基线复核）。
- **为什么不做硬过滤**：硬过滤会把"被问到的朝代"连同事件本身剔除——鸣条之战朝代为
  "夏"，问"与商朝的关系"时若把"商"当硬筛选，图谱/文本/融合全为 0、直接拒答
  （首轮评测中 B01/E01/R05/T03 四题即由此被误拒）。该机制与词典是否补别名无关：
  实测给词典补 `商朝→商` 后，若仍走硬过滤，E01 会再次被打回拒答。
- **回归守护**：`tests/test_f02_regression.py`（四题不得拒答；补别名后仍不得拒答）、
  `tests/test_dynasty_filter.py`（识别语义）、同名消歧用例（问句朝代偏好）。
- 改这里要同步改：`contracts/` 的 `F02Output` 字段、[data-contract.md](data-contract.md)
  的"F02 内部输出"段、F03 策略前置重排、F04 返回序逻辑。

### 实体纠正重查

纠正重查是一次新请求，不修改已结束的历史回答；后端以 `corrected_entities` 覆盖 F02 自动识别结果。
支持三种操作：

| 操作 | 字段 | 说明 |
| --- | --- | --- |
| `add` | `entity_type`、`name` | 新增实体 |
| `replace` | `entity_type`、`original`、`replacement` | 替换实体 |
| `remove` | `entity_type`、`original` | 删除实体，不传 `replacement` |

1. `add` 的 `name` 与 `replace` 的 `replacement` 必须填写 F02 输出中的 `standard_name`，
   避免前端回传"涿鹿县"等别名后 F02 再次做归一化。
2. 纠正重查必须携带上一轮会话历史，便于 F02 对"它""这场战争"等指代继续消解。
3. `remove` 后问题不再包含任何实体时，`entities` 输出为空，请求按纯文本检索处理；
   无有效文本证据时由 F06 拒答。
4. 前端取消当前进行中的流后，再发起纠正重查。

### 依赖与前置条件

F09 输出标准化实体词典、别名表、朝代别名与现代地名映射。

### 验收标准

1. 演示问题中的主要实体可以被正确识别。
2. 已知别名可以被映射到标准实体。
3. 错误识别对最终问答的影响可被后续检索分数控制。
4. 识别结果对用户可见，并允许用户手动纠正。

## 三、F03 图谱检索通道（GraphRAG）

### 功能作用

利用已治理的知识图谱数据，回答需要精确关系的事实类问题，例如事件参与方、事件发生地点、
事件之间的因果或顺承关系。

### GraphRAG 在本项目中的定义

本项目不使用 Microsoft GraphRAG 的"从零抽图 + 社区摘要"整套方案——知识图谱已由旧项目抽取完成。
本项目的 GraphRAG 指**知识图谱增强检索**：

1. 旧图谱经 F09 治理后形成干净图谱快照；
2. F02 先从问题中识别并归一实体；
3. F03 按问题中的实体在图谱快照中检索结构化事实；
4. 结构化事实作为证据进入 F05，与 F04 的文本检索结果共同参与最终回答。

```text
用户问题 → F02 实体识别与消歧 → 在图谱快照中匹配标准实体
        → 判断问题类型并执行图谱查询 → 返回结构化事实/三元组/子图/路径
        → F05 与文本检索结果合并排序
```

### 实现口径

1. F09 生成预构建图谱快照文件，服务启动时加载为内存索引，**不在请求阶段重新建图**；
   RAG 内置只读快照图谱，不依赖旧 Neo4j 服务。
2. 用 F02 输出的标准实体名匹配图谱节点；实体不存在、实体孤立或问题类型不适合图谱查询时，
   **不返回虚构关系**，改由文本检索与实体卡片处理。
3. 图谱检索结果统一转换成三元组形式，每条保留关系类型、方向、来源、置信度等元信息。
4. 朝代、战争类型筛选条件作为图谱检索的过滤条件；F02 的朝代软偏置在策略执行前重排命中节点。
5. 支持实体详情、关系、1 跳邻居、有限深度路径等查询。
6. 孤立节点保留在数据快照中，不因缺少关系而删除，也不进入路径逻辑。
7. 图谱快照带版本号，F03 与 F09/F11 索引使用同一数据版本。

### 问题类型与图谱查询策略

| F02 问题类型 | F03 图谱查询策略 |
| --- | --- |
| `single_entity` | 查询实体属性、1 跳邻居，返回实体卡与直接关系 |
| `relation` | 查询事件或实体相关的组织、人物、地点关系 |
| `event_event` | 查询两个事件之间的直接关系或两跳路径 |
| `comparison` | 分别查询比较对象的一跳子图，不做强行合并 |
| `timeline` | 查询相关事件及时间字段，图谱只负责关系与事件锚点 |
| `background` | 图谱只返回实体基础上下文，主体交给文本检索 |
| `unknown` | 对**主实体（首个命中实体）**执行 1 跳查询作为候选，不强推路径结果；多实体时其余实体由文本通道覆盖 |

支持的具体查询：单实体介绍；事件-人物/组织/地点关系；事件-事件因果、顺承、包含、并列关系；
多事件直接关系或两跳路径；地点参与的战争检索。

示例：

- "赤壁之战有哪些参战方"：匹配"赤壁之战"事件，查询其组织、人物关系。
- "长平之战和邯郸之战之间有什么关系"：匹配两个事件，查询 `event_event` 关系。
- "洛阳发生过哪些战争"：匹配"洛阳"地点，查询所有关联事件。
- "阪泉是什么"：若"阪泉"孤立，不执行关系路径检索，只返回实体信息与文本证据。

### 规则推理边（沿快照一并加载）

图谱索引同时加载原始关系与**规则推理边**（快照目录内的 `inferred_relations.json`，
字段口径见 [data-contract.md](data-contract.md) 的"规则推理产物"节）：
事件类问题因此能命中「隶属于战役 / 间接因果 / 连续演进」这类由 20 条规则推导出的关系，
战役隶属、因果链等多跳问题不需要在线展开即可回答；推理边的证据带 `kg_inference` 与
规则/溯源标记，引用标题标注来源规则，可回溯到原始关系行。缺该文件即降级为纯原始图谱。

### 图谱证据输出格式

```text
subject: 源实体名称        subject_type: 事件/人物/组织/地点
relation: 关系类型         object: 目标实体名称
object_type: 目标实体类型  evidence: 证据原文或来源标识
confidence: 置信度         source_type: 结构化数据来源
```

例如 `长平之战 / 事件 --发起方--> 秦军 / 组织`，`evidence: 事件-组织关系表`，`confidence: high`。
该格式输出给 F05，再由 F05 统一合并文本证据并交给 F06。统一字段定义以
[data-contract.md](data-contract.md) 为准。

### 已收口的边界（原先的待确认问题）

1. **图谱最大查询深度**：指从问题实体出发最多经过多少条关系边再返回结果。深度越大检索越全，
   噪音与耗时也越高。**结论**：除 `event_event` 策略走两跳路径外，其余策略均按 1 跳邻接定档
   （深度经 F10 评测确认，见 `server/graph/search.py` 与 `server/graph/query_strategies.py`）。
2. **图谱展示方式**：知识面板默认展示一跳子图，关系型问题按需展示完整路径会让图谱变拥挤。
   **结论**：panel 子图 = 命中实体 + 1 跳邻居 + 融合证据两端实体（≤ 24 节点），
   **不单独做"路径视图"**；`event_event` 的两跳路径以三元组证据形式进入回答，
   其两端实体可在子图中呈现（见 F07 模块清单第 3 项）。

### 依赖与前置条件

1. 已完成实体消歧与孤立节点标记，生成干净图谱快照（关系补边待人工审核回填，见 F09）。
2. F02 实体识别结果可以稳定匹配图谱节点。
3. 图谱检索结果格式可被 F05 证据融合模块使用。
4. 图谱快照带版本号，F03 与 F09/F11 索引使用同一数据版本。

### 验收标准

1. 已连通实体可以查询到正确关系。
2. 孤立节点不会导致系统返回虚构关系。
3. 图谱检索可以返回可直接展示的子图数据。

## 四、F04 文本检索通道

### 功能作用

从事件卡片、原文片段与关系证据中找回与问题相关的文本证据，
用于补充图谱无法表达的背景、过程和细节。

### 输入与输出

- 输入：改写后问题、问题类型、归一化后的实体信息、朝代/战争类型筛选条件。
- 输出：Top N 文本片段、片段类型、来源、分数、相关实体，字段遵循 [data-contract.md](data-contract.md)。

### 三模式与部署级开关

`TEXT_MODE` 是**部署级开关**（切换需重启），三模式可用：

| 模式 | 实现 |
| --- | --- |
| `keyword` | SQLite FTS5 / BM25，中文分词后检索 |
| `vector` | Chroma 持久化集合 + 云端 embedding（cosine） |
| `hybrid` | 关键词 + 向量融合，策略由 `TEXT_HYBRID_STRATEGY` 决定 |

向量不可用时自动降级 `keyword`，实际执行模式随 `text_results` 事件的 `mode` 字段上报。

### 实现口径

1. F11 负责文本切分、关键词索引与向量索引构建，F04 不重复处理文本切分，只消费索引。
2. 文本片段必须保留来源、原文、相关实体等元信息。
3. 不同检索模式的原始分数**必须先在各自模式内做 min-max 归一化到 0–1 再输出**，
   避免 BM25、向量分数与混合分数无法统一比较（规则见 [data-contract.md](data-contract.md)）。
4. "命中关键词"只在关键词检索模式下返回，不作为向量检索的强制输出。
5. `keyword_mode` 参数供评测使用：`and_or`（默认）、`and`（仅 AND，用于量化"长改写问题
   AND 命中 0"的失效面）、`or`（仅 OR，观察兜底召回质量）。仅评测链路显式传入，
   常规问答默认路径零变化。
6. `and_or` 的实际口径（`server/text/searcher.py`）：先取 AND 结果，
   **AND 命中不足 3 条时并入 OR 结果**（不是只在 AND 为空时才兜底）——
   长改写问题的 AND 常只命中 1–2 个片段，旧口径会把 OR 里更相关的片段整批丢掉；
   合并后统一去重、筛选与分数归一化。
7. 筛选条件的语义：`event_type` 只对**有该元数据的片段**（事件卡片、已关联事件的关系证据）生效，
   原文片段（无事件归属）放行。
8. F02 的朝代软偏置在文本侧只影响检索返回序，最终顺序由 F05 按相关分决定（当前不改变最终排序）。

### 实测结论（已定档）

1. **检索模式已在 F10 对照评测定档**：`TEXT_MODE=hybrid`、`TEXT_HYBRID_STRATEGY=rrf`
   （rrf 文本召回 97.0% 优于 weighted 95.2% / fallback 94.6%，fallback 等于没做融合）。
   部署级开关仍保留三模式可切换，默认按定档值运行。
2. 向量通道弥补了长改写问题的 AND 失效：回答覆盖 71.7% → 85.1%。

### 依赖与前置条件

F11 已完成切分与索引构建；索引带版本号，F04 读取的索引与 F09 快照版本一致。

### 验收标准

1. 演示问题可以找回相关文本片段。
2. 每条结果都能追溯到来源。
3. 文本片段与图谱事实重叠时不会直接冲突。
4. 输出字段符合 [data-contract.md](data-contract.md)，并可被 F05 直接消费。

## 五、F05 检索结果融合与重排

### 功能作用

把图谱检索与文本检索的结果合并成一个统一、有序、可去重的证据集合，供回答生成模块使用；
同时负责组装 F07 所需的 panel 数据，是 **panel 事件的唯一后端装配方**。

### 输入与输出

- 输入：图谱检索结果、文本检索结果、问题实体、问题类型、筛选条件、
  F09 快照中的实体卡/时间/坐标数据。
- 输出：排序后的统一证据列表、引用编号、来源、置信度、冲突提示、panel 数据。

### 实现口径

1. 使用 [data-contract.md](data-contract.md) 的统一证据结构，区分图谱事实、原始文本、
   事件卡片、关系证据。
2. 按问题类型调整权重：关系问题提高图谱权重，背景问题提高文本权重；对重复实体与重复内容去重。
3. 为最终进入提示词的证据统一分配 `citation_index`（由 F05 分配，F06 使用，F07 展示）。
4. 组装 panel 数据：subgraph 的 `nodes`/`edges` **只在此处生成一次**，panel 是 subgraph
   的唯一输出来源，F07 不再自行拼接第二套 subgraph。
5. `timeline` 按朝代分组、组内按可解析的 `start_date` 升序排序（起讫年份需从
   "前2179年 / 公元前26世纪"等文本解析，无法解析的条目保持数据原序并置于组内末尾）；
   时间不详的条目归入"时间不详/仅知朝代"分组置尾；`map_points` 只保留有坐标地点。
6. `field_vs_triple` 冲突使用 F09 输出的关系-事件卡片字段映射表（不硬编码）。

### 冲突判定口径

1. 初版只做**结构化**冲突判定，不做通用语义矛盾检测。
2. 范围限定为：
   - **`different_object`（graph_triple 之间）**：同 subject、同 relation、不同 object；
     且**仅对单值关系生效**——只判定 field_map 中 exact 单值组如发起方/防守方；
     主帅/将领等多值关系是并列事实行，多个 object 不报冲突，避免误报
     （实现见 `server/fusion/conflict.py`）。
   - **`field_vs_triple`**：图谱三元组与事件卡片结构化字段不一致。
3. `raw_text` 与 `evidence` **不参与**自动冲突判定，只作为说明性证据保留。
4. 冲突证据**全部保留**并传递给 F06，不因简单规则被误删；F06 不擅自裁决。
5. 冲突以 `conflicts` 字段随 `fusion` 或 `citations` 事件推送，前端据此提示"存在不同说法"。

### 已收口的边界（原先的待确认问题）

1. **图谱证据与文本证据冲突时怎么处理**：初版策略已确定为"结构化冲突才输出 conflicts，
   文本证据不参与自动冲突判定，冲突证据全部保留"。是否引入优先级投票等机制，
   等 F10 出现真实冲突案例后再微调。
2. **是否引入独立排序模型**：独立排序模型能提升排序质量，但增加模型依赖、部署复杂度与耗时。
   当前使用规则融合 + 来源权重排序；该问题作为**可配置项保留**，不强制二选一，
   是否有提升空间由 F10 评测说明。

### 依赖与前置条件

图谱检索与文本检索均有可用输出；证据结构符合 [data-contract.md](data-contract.md)；
图谱与文本结果均携带来源和版本号；可以从 F09 快照读取实体卡、时间和坐标数据。

### 验收标准

1. 同一问题不会重复返回大量相同内容。
2. 关系型问题优先命中图谱证据。
3. 答案中的引用编号可以对应到具体证据。
4. 冲突证据被保留并传递给 F06，不会因简单规则被误删。
5. panel 数据由 F05 输出，F07 只读 panel。

## 六、F06 证据溯源回答生成

### 功能作用

根据融合后的图谱事实与文本证据生成最终答案，要求答案有引用、可溯源、
不编造知识库中不存在的内容。

### 输入与输出

- 输入：用户问题、改写后问题、归一化实体、排序后的证据列表、会话上下文、筛选条件。
- 输出：答案正文、引用编号、证据摘要、检索状态（含首思考时延与推理增量条数），通过 SSE 推送；
  原始思考内容默认不外发。

### 实现口径

1. 默认使用 `deepseek/deepseek-v4.1-flash`（中转模型 id；官方口径为 `deepseek-flash`），
   模型配置通过环境变量管理。
2. 构造"图谱事实 + 文本证据 + 引用编号"的统一提示词，要求模型只依据证据回答并在文中标注引用编号。
3. 没有足够证据时生成拒答文案，而不是强行编造。
4. 支持流式输出，并把检索过程摘要一并返回前端。
5. 多轮会话上下文后端按近期轮次和字符预算截取（初版建议最多 2 到 4 轮）。
6. 缓存键使用 F02 改写后的 `rewritten_question`、会话历史摘要、筛选条件、数据版本、模型版本
   与文本检索模式，**不直接使用可能产生多轮歧义的原问题**。
7. 主模型调用配置超时、重试和备用模型；主模型失败后自动降级，避免演示单点故障。
8. 证据中存在 `conflicts` 时，回答不得只陈述单一说法，应同时提示不同表述并分别标注引用。
9. 正文已开始输出后**不再透明重试**（`server/generate/llm_client.py`）：失败以 `interrupted`
   收敛并保留部分正文，避免两次尝试的文本被拼成重复答案。

### 拒答判定规则

1. 图谱证据为空且文本证据为空时，直接拒答（`finish_reason=refused`）。
2. 实体识别为空、文本证据存在但与问题无共享词时依据不足拒答；向量/hybrid 模式下证据可能
   按语义命中而不含问题原词，因此该规则放宽为「无共享词 **且** 证据最高分低于阈值」才拒答。
3. `score` 不单独作为拒答阈值；向量/hybrid 模式下作为低分兜底信号之一
   （`VECTOR_REFUSAL_MIN_SCORE`，默认 0.25），仅与第 2 条的「实体为空且无共享词」叠加生效。
   关键词模式下仍是严格的无共享词即拒答。
4. 大模型判断"无法依据证据回答"时按拒答路径返回。识别口径：正文前 200 字内命中固定拒答句式
   （提示词要求模型使用的"依据现有资料无法确认"及其等价表述）且全文不含引用编号时，
   判为模型自拒；已给出引用的"局部不确定"表述不判自拒
   （实现见 `server/generate/refusal.py` 的 `detect_model_refusal`）。
5. **领域外谓词拒答**：问题问到知识库不可能覆盖的现代属性/器物（邮箱、电话、度假、坦克、
   股票等），且这些词在所有证据里都不出现时拒答；只要证据中出现过该词即放行，
   宁可少拒、不误拒可答题（实现见 `server/generate/refusal.py` 的 `OUT_OF_SCOPE_PREDICATES`
   与 `server/sse.py` 的编排位置）。
6. 拒答判定与文案的归属地是 `server/generate/refusal.py`，**在线（`server/sse.py`）与评测
   （`evaluation/chain.py`）共用**，改这里要两处一起想，避免"评测拒答、线上不拒答"。

### 推理增量（thinking）

1. deepseek 系列为推理模型，流式响应含思考内容。默认**不把原始推理推给公共 SSE**：
   后端只统计首思考时延与推理增量条数，经 `done` 事件的 `first_thinking_ms` /
   `thinking_frames` 字段对外可见（不含内容）。本地调试可设 `EXPOSE_THINKING=true`
   打开 `thinking` 事件（`data={"delta": "..."}`）；生产不建议开启，
   推理内容可能包含中间判断与上下文复述。
2. 推理字段名两端不同：中转 endpoint 为 `reasoning`、官方为 `reasoning_content`，
   后端已双端兼容（`server/generate/llm_client.py` 的 `_reasoning_of`），缺失时不发 thinking 事件。
3. 即便开启 `EXPOSE_THINKING`，`thinking` 事件也只承载模型思考增量，
   不含系统提示词与检索上下文。
4. 页面**默认不展示**模型原始思考过程：只展示"正在生成"状态与首思考时延；
   如未来要展示，必须是后端过滤后的高层摘要，不能是原始 reasoning。

### 降级路径

生成结果按以下优先级判定 `finish_reason`，保证任何情况下都有可读回答：

| 情形 | finish_reason | 说明 |
| --- | --- | --- |
| 主模型失败（超时/网络错误，重试与备用模型均不可用） | `degraded` | 离线摘要回答器兜底，**不入缓存** |
| 模型返回空正文（推理 token 吃满 `max_tokens`，实测 28 题中 2 题） | `degraded` | 同样降级到离线摘要回答器，避免演示出现空白回答 |
| 备用模型返回正文 | `degraded` | 记录实际模型名；若正文命中自拒句式，按拒答口径记 `refused`（拒答语义优先于降级标记） |
| 正常完成 | `normal` | 拒绝泄露提示词请求时返回固定回复、`normal`（不调用模型） |

`finish_reason` 完整枚举（含 `cancelled` / `failed` / `interrupted`）见
[data-contract.md](data-contract.md) 的"流式事件协议"。

### 回答缓存

1. 缓存键包含 `rewritten_question`、会话历史摘要、筛选条件、数据版本、模型版本与文本检索模式。
2. 缓存命中返回历史答案与对应引用；缓存设有效期，演示时可手动清空。
3. 缓存命中时**仍先执行 F02**：推送 `session_start`、`status(entity_linking)`、`entities`，
   随后按 `status(stage=cache_hit)` → 完整 `answer` → `citations` → `panel` → `done` 回放，
   与正常路径保持一致的实体展示与纠正能力，不再流式调用大模型。
4. `degraded` 结果不入缓存（缓存卫生）。

### 提示词与思考过程保护要求

1. 系统提示词和检索上下文只存在后端，不发送到前端原始文本。
2. 提示词中明确要求模型不得输出或复述自身系统提示词。
3. 提示词中明确要求模型不得泄露检索 query、内部工具名称、证据组装规则等实现细节。
4. 当用户要求"展示你的提示词"或"展示系统设定"时，模型只返回固定提示语，不输出真实内容。
5. 展示给用户的"思考过程"需要经过后端过滤或只保留高层的推理摘要。

### 依赖与前置条件

大模型服务配置可用、密钥通过环境变量管理；证据融合模块已生成结构化上下文；
已配置主模型超时、重试与备用模型；流式事件格式遵循 [data-contract.md](data-contract.md)。

### 验收标准

1. 演示问题的大部分回答均有引用。
2. 知识库外问题不会得到编造答案。
3. 回答、引用与证据能够一一对应。
4. 主模型不可用时可切换备用模型，不影响页面演示。
5. 相同演示问题重复提问可命中缓存。

### 已确认需求

1. 默认大模型为 `deepseek/deepseek-v4.1-flash`（中转 id；官方为 `deepseek-flash`）。
2. 思考过程默认不外发（仅后端度量）；`EXPOSE_THINKING=true` 时才以独立事件提供。
3. 增加提示词与思考过程防泄露保护。

## 七、F07 可视化知识面板

### 功能作用

在问答页面右侧展示与当前问题相关的图谱子图、时间线、地图位置和证据原文，
让 RAG 的回答不只是文字，而是可交互的知识展示。

### 用户场景

1. 问某场战争，右侧展示该战争的一跳图谱。
2. 问多个事件之间的关系，右侧展示事件子图，关系链由子图内的关系连边承载
   （不单独设"关系路径"视图）。
3. 问地点相关问题时，右侧可展示历史地图或现代位置。
4. 点击图谱中的节点后可继续追问该实体（画布内节点与下方实体按钮均可点击）。

### 知识面板模块清单

| # | 模块 | 状态与口径 |
| --- | --- | --- |
| 1 | 当前实体信息卡 | 展示问题涉及的事件、人物、组织、地点等实体基础信息；事件卡额外展示攻方、守方、作战行动、地点与历史影响（从快照 `event_cards` 装配，字段口径见 [data-contract.md](data-contract.md) 的 `entity_cards` 段） |
| 2 | 图谱子图 | 展示当前事件或实体的一跳关系，关系边带类型标签 |
| 3 | 关系路径 | **未单独设视图**——事件之间的关系链由图谱子图（第 2 项）的关系连边承载；F05 panel 数据不输出独立路径字段，独立路径视图属后续增强 |
| 4 | 引用与证据 | 展示回答引用的证据原文、来源和置信度 |
| 5 | 时间线 | 问题包含多个事件或时间信息时，展示相关事件时间线 |
| 6 | 地图 | 问题涉及有坐标的地点时展示地图位置；无坐标时降级为地点列表 |
| 7 | 节点追问 | 图谱节点（画布内节点与下方实体按钮）支持点击，直接生成"介绍一下 XX"式追问；原设想的"继续提问该实体 / 查看实体详情"操作菜单**未实现** |

### 模块展示策略

1. 默认展示：当前实体信息卡、图谱子图、引用与证据。
2. 条件展示：时间线、地图根据问题类型自动出现——**当前为标签页手动切换**，
   未实现按问题类型自动切换标签；每轮新消息重置回"引用证据"标签页。
3. 知识面板采用标签页或折叠区域，避免同时堆叠过多内容。
4. 点击图谱节点继续提问时，生成"介绍一下 XX"式追问语句
   （"XX 参与了哪些战争"等多句式追问**未实现**）。

### 输入与输出

- 输入：当前问题、回答正文、SSE 中的 panel 数据、图谱证据、文本证据。
- 输出：实体卡、图谱子图、时间线、地图点、证据列表。

### 实现口径

1. 使用前端图表库绘制图谱子图与时间线；地图数据根据地点经纬度生成。
2. 每个证据卡片可展开原文，并支持从回答引用跳转。
3. 知识面板数据格式由后端统一返回（F05 装配），前端只负责渲染；优先消费 SSE 的 `panel` 事件。
4. 初版地图使用现代底图加历史地点标记；历史地图底图需要额外素材与授权，后续再评估。
5. `citations` 或 `fusion` 事件携带 `conflicts` 时，证据卡片可显示"存在不同说法"标识。

### 数据基础与降级策略

1. 时间线按事件 `start_date` 排序；时间缺失或仅到朝代时归入"时间不详/仅知朝代"分组，
   不强行插入时间轴。事件时间解析规则在 F09 治理报告中记录。
2. 地点坐标覆盖率由 F09 治理报告评估；覆盖率不足时地图模块以地点列表为主。
   当前坐标覆盖 4,819/5,316。
3. 坐标缺失的地点不报错，自动降级为文字地点卡。
4. 事件卡的叙事字段（攻方/守方/作战行动/历史影响/地点）缺失时**整行不渲染**，不做空占位。
5. `map_points` 选点口径（`server/fusion/panel_builder.py`）：同名地点在快照里有多行
   （跨朝代重复），按坐标聚类后**优先取带地址线索（省/今址）的簇**
   （实测：长平→山西高平市、河内→河南沁阳；无地址线索的行会被地理编码落到同名村庄），
   簇内重复行合并、`events` 取并集；点位按相关事件数排序，最多 8 个。

### 依赖与前置条件

图谱检索结果包含可绘制的关系数据；地点数据包含可用坐标或文本位置；
前端页面已预留知识面板区域；前端图表组件支持节点点击事件。

### 验收标准

1. 演示问题时知识面板不会空白。
2. 图谱、时间线、地图等模块互相不遮挡。
3. 没有坐标的地点不会导致页面报错。
4. 点击图谱节点可以发起新的追问。
5. 时间缺失或坐标缺失时，知识面板有明确的降级展示，不出现空白模块。

1. 旧项目原始正文文本。
2. 事件、地点、人物、组织四类实体数据。
3. 事件-地点、事件-人物、事件-组织、事件-事件关系数据。

## 十、F10 问答效果评测

### 功能作用

通过固定问答集和评测指标，持续验证 RAG 问答系统的效果，
并为比赛材料提供量化证据。

### 用户场景

1. 开发过程中判断检索与回答是否达到预期。
2. 对比图谱加文本双通道与纯文本 RAG 的效果差异。
3. 输出评测报告用于参赛方案和技术说明。
4. 答案最终正确性的目标口径为人工评分，不默认使用模型评分。

### 评分与审核口径（重要）

> - 题库审核与 39 条答案/引用评分的主体**当前为 AI 代理**
>   （reviewer 记为「AI代理审核-ZCode(deepseek-v4-flash)」），并非人工；
>   本节的"人工审核 / 人工评分"描述的是**目标口径**，当前交付以 AI 代理口径为准。
> - 最新 hybrid/LLM 链路的 run 尚无人工评分回填；现有正确性结论
>   （25 correct / 3 partial / 0 incorrect）为 AI 代理评分口径。
> - 如需正式口径：人工复核审核报告的存疑清单，并回填最新 run 的评分。

### 输入与输出

- 输入：黄金问答集、相关文档标注、RAG 系统输出、真实数据治理报告。
- 输出：人工评分表、评测报告、错误样例、指标统计。

### 实现口径

1. 建立 30 到 50 条黄金问答集，覆盖实体介绍、关系、因果、时间线、背景等类型。
2. 黄金问答集的目标口径为人工审核和确认（当前交付由 AI 代理审核）。
3. 答案正确性、引用正确性等主观结果的目标口径为人工评分（当前交付由 AI 代理评分）。
4. 检索召回、图谱命中、耗时等客观结果由脚本自动统计。
5. 同一问题可运行不同检索配置，保存对比结果；评测脚本输出指标报告与失败案例。
6. 人工评分需要提前定义评分说明，避免不同审核人标准不一致。
7. **评测强制绕过回答缓存**：缓存键已含文本检索模式与数据/模型版本，
   但跨配置共享仍会污染对比结论，故评测一律绕过。
8. 评测与在线链路**共用同一套 `server/generate`**，避免"评测通过、线上另一种回答"。

### 人工评分规则

| 维度 | 取值 |
| --- | --- |
| 答案正确性 | `correct`（正确且依据充分）/ `partial`（方向正确但信息不完整）/ `incorrect`（错误）/ `unknown_answer`（应拒答时正确拒答） |
| 引用正确性 | `supported`（引用可验证且支持答案）/ `unrelated`（引用存在但与该结论无关）/ `unsupported`（关键结论没有引用支持） |

每条评测记录保存问题、系统答案、人工评分、备注和对应证据。

### 检索召回标注

1. 黄金问答集中的每条问题预先标注应该被召回的相关文档或实体。
2. 标注结果用于计算 `recall@5`、图谱命中率等客观指标。
3. 相关文档标注由人工完成，并在评测报告中记录标注版本。

### 题库统一说明

1. F08 示例问题与 F10 黄金问答集**使用同一题库管理**。
2. 示例问题从已通过审核的评测题中挑选（当前审核主体为 AI 代理）。

### 两处观测口径（避免误读报告）

1. `trace.finish_reason` 只有 `normal` / `degraded` / `refused`，**不反映截断**
   （截断仅日志告警）。
2. `ok/n` 是"回答里出现标注词"的机械口径，真实 LLM 用自然语言作答会漏词
   （出现过"28/28 ok 但 0 correct"与"24–26/28 ok 但回答更完整"两种情形）。
   **正确性以评分表为准。**

### 依赖与前置条件

黄金问答集需要审核，确保答案可依据现有数据回答；RAG 核心检索和生成链路已完成；
人工评分说明已确定；相关文档标注已完成。

1. 评测可以在一条命令下重复运行。
2. 报告能区分答案错误、引用错误、检索失败和无证据问题。
3. 可以输出"图谱加文本双通道"与"纯文本检索"的对比结论。

- 输出：文本片段表、片段元信息、关键词索引、向量索引、索引版本清单、索引构建报告。

### 文本切片数据源

三类数据全部切片入库，每个片段都标记片段类型（`raw` / `event_card` / `evidence`）：

1. **原始正文**：旧项目中的战争史原文，用于回答背景、过程和详细描述类问题。
2. **事件卡片**：以事件为单位整理出的结构化描述，包含事件名、朝代、时间、参与方、结果、影响等。
3. **证据片段**：关系证据、引用原文和来源片段，用于回答需要精确引用和溯源的问题。

原始正文与事件卡片之间存在内容重叠属于正常现象。检索阶段通过片段类型、来源和排序策略
共同控制，**不要求物理去重后只保留其中一种**。

### 实现口径

1. 读取原始正文、事件卡片、证据片段、地点/人物/组织描述等文本语料。
2. 事件卡片以"事件"为最小单元，原文和证据按内容边界切分。
3. 每条片段保留片段类型、事件名、事件类型、来源、朝代、时间、相关实体等元信息。
4. 对过长文本按句子边界二次切分并保留前后重叠，避免切分截断关键信息。
5. 每个片段都需要能回溯到原文档、原事件、原证据和来源。
6. 使用云端中文文本向量模型生成片段向量，写入本地向量库（Chroma 持久化集合）。
7. 同时建立关键词索引（SQLite FTS5 + jieba 分词）。
8. 输出索引构建报告：片段数量、向量数量、切分参数、缺失文本数量。
9. 每次构建生成新索引版本号，片段 ID 与 F09 数据版本对应。

### 切分与索引参数（生产实测值）

| 项 | 值 |
| --- | --- |
| 切分参数 | `max_chars=800`、`overlap_chars=80` |
| 片段总数 | 9,544（`raw` 934 / `event_card` 1,107 / `evidence` 7,503；FTS 可检索 9,544） |
| 向量 | `text-embedding-v4`（百炼），1024 维，cosine，集合 `chunks_v1` |
| 关系证据元数据 | 按事件卡片补齐 `event_type`，供筛选条件使用 |

### 向量数据库选型

选型按轻量、可本地运行、不依赖重型服务的要求定档为 **Chroma 持久化集合（HNSW）**，
检索只走 `vectors/chroma/`；`ids.json` 记录片段 id 顺序（与矩阵/集合行对齐），
`embeddings.npy` 是审计副本（不参与检索，换机器可免重嵌入）。

1. 向量模型接口和具体模型名通过配置文件管理，密钥使用环境变量。
2. 云端接口不可用时，向量模式自动降级为关键词检索，不改变现有索引结构。

### 依赖与前置条件

F09 已生成文本语料快照；云端向量模型接口可用（无密钥时只建关键词索引）。

### 验收标准

1. 文本切分后没有无法回溯来源的片段。
2. 向量索引和关键词索引可以正常生成。
3. F04 可以读取索引完成检索。
4. 索引构建报告记录完整切分参数和构建数量。
5. 索引带版本号，F04 能确认其与 F09 快照版本一致。

### 已确认需求

1. 使用云端文本向量模型。
2. 原始正文、事件卡片、证据片段全部进行切分和索引构建。
3. 使用原文建库前，需确认数据来源授权或使用已授权文本。

## 十二、跨功能约定与未完成项

### 改动前必读的三条硬约定

1. **改字段先改契约**：涉及 [data-contract.md](data-contract.md) 的字段调整，
   必须先更新该文件与 `contracts/` 中的定义，再同步受影响的功能节与前端类型镜像。
2. **数字只有一处**：版本、测试数、数据计数只在 [current-status.md](current-status.md) 维护，
   由 `scripts/check_docs.py --strict` 机械核对（含数据计数与快照/索引清单比对）。
3. **版本必须一致**：F03 读快照、F04 读索引，两者版本号必须相同；
   生产档（`RAG_REQUIRE_ACTIVE_VERSION=true`）下必须显式固定版本。

### 拒答与证据口径不变量

1. 无证据直接拒答 → 双通道证据带引用 → 生成只允许引用已编号证据，三层防幻觉不可拆。
2. 拒答判定与文案的归属地是 `server/generate/refusal.py`，在线与评测共用。
3. 冲突证据全部保留并传给 F06，不因简单规则被误删。
4. 推理边与原始关系必须可区分（`source_type` / `inferred` / `rule_id`），
   否则引用与证据无法溯源。
