# F01 智能问答主界面

- 功能编号：F01
- 状态：已完成（RAGv3 前端单页；阶段交付与设计口径见 [../CHANGELOG.md](../CHANGELOG.md)）
- 创建时间：2026-09-03

## 功能作用

为使用者提供整个 RAG 问答页面的核心入口，让使用者可以输入历史战争相关问题，并看到完整的问答结果与检索过程。

## 页面形态

本项目只做一个用户可见页面：智能问答页。F07 知识面板、F02 实体识别结果、检索过程和引用证据都呈现在这一个页面内，不再拆分多个页面。

## 用户场景

1. 使用者打开页面后直接进入问答界面，不需要阅读项目介绍后才能提问。
2. 使用者可以连续追问同一场战争、同一人物或同一地点。
3. 使用者可以查看答案来源、图谱子图、时间线和地图信息。
4. 使用者在同一页面内保留本次会话的历史问答记录，并可点击任意一轮回到该轮的完整回答与知识面板。
5. 使用者可以开多个会话（新建/切换/重命名/删除），每个会话独立保存各自的问答记录，
   左侧按“会话列表 → 该会话的轮次列表”两级展示。
6. 使用者可以把当前会话导出为 Markdown（回答正文 + 引用来源清单），用于归档或分享。
7. 使用者可以选择朝代、战争类型等筛选条件后提问。

## 输入与输出

- 输入：用户问题文本、会话 ID、会话历史、朝代/战争类型筛选条件、纠正后的实体、页面操作。
- 输出：流式回答、过程事件、引用列表、实体识别结果、知识面板数据、错误提示。

## 实现思路

1. 采用全新的独立前端页面，不与旧前端共享页面代码。
2. 页面结构为左侧提问历史栏（可折叠）、中间对话区、右侧知识面板区；窄屏下历史栏与知识面板改为抽屉。
3. 问答请求发送到 RAG 后端，由后端完成实体识别、双通道检索和回答生成。
4. 回答支持流式输出，展示“正在识别实体、正在检索图谱、正在检索文本、正在生成回答”等过程。
5. 页面提供新建会话、导出会话（Markdown）、复制回答、展开引用等基础操作。
6. 会话历史在本页面内保留，刷新后仍可查看；多轮追问时把近期历史随请求发送给后端。
   左侧提问历史栏列出每一轮（含失败/取消/被重查取代的轮次，带状态徽标），点击即把知识面板
   切到该轮并滚动定位到聊天区对应消息；新提问自动回到最新视图。
   多会话（2026-09-20 借鉴项 P1）：会话列表在轮次列表之上（可折叠），支持新建/切换/重命名/删除，
   会话标题按首条提问的前 15 字自动生成、可改名；会话数据保存在浏览器本地
   （schemaVersion 3，旧版本数据自动迁移或隔离），会话数与每会话消息数均有上限，超限按最近使用裁剪。
   会话级导出（同日借鉴项）：导出当前会话为 Markdown，含轮次时间、问题、回答正文与
   **引用编号到来源的对照清单**（正文里的 `[n]` 脱离界面后仍可溯源）。
7. 页面提供朝代、战争类型等筛选入口，筛选条件同时传给图谱检索和文本检索，不只注入提示词。
8. 请求与 SSE 事件字段遵循 data-contract.md 定义。
9. 用户纠正实体后发起新的问答请求，不修改已结束的历史回答。

## 依赖与前置条件

1. RAG 后端服务可正常启动。
2. 问答相关的检索索引已经构建完成。
3. 大模型服务配置可用。

## 验收标准

1. 页面打开后无需登录即可提问，不依赖 F08 演示模式。
2. 提问后可以展示带引用的回答。
3. 回答过程中的关键检索步骤对使用者可见。
4. 页面不出现旧版后台的菜单、模板内容或无关文案。
5. 筛选条件会同时影响图谱检索和文本检索结果。
6. 提问历史可点回任意一轮：知识面板恢复该轮的引用证据、实体卡、图谱子图、时间线与地点数据，
   并明确提示当前不在最新一轮（可一键返回最新）。
7. 新建/切换/删除/重命名会话后刷新页面，会话列表与当前会话保持；旧格式本地数据能自动迁移
   或隔离，且不出现报错。
8. 任意一段会话可导出为 .md 且 Markdown 渲染正常，正文中的引用编号能与来源清单逐条对应。

## 已确认需求

1. 保留会话历史记录，并支持从历史记录返回任意一轮的问答与知识面板。
2. 支持按朝代、战争类型筛选后提问。
3. 支持多会话管理与会话级 Markdown 导出（2026-09-20，借鉴旧「历史问答助手」；边界见
   [RAG借鉴旧问答系统-需求分析](../RAG_v2/RAG借鉴旧问答系统-需求分析.md) §4.2/§4.3）。
