# F03 图谱检索通道（GraphRAG）

- 功能编号：F03
- 状态：已完成（RAGv2 服务版；检索深度 1~2 跳按 F10 再调）
- 创建时间：2026-09-03
- 实现说明：见 [../CHANGELOG.md](../CHANGELOG.md) 与 [architecture.md](../architecture.md)

## 功能作用

利用已治理的知识图谱数据，回答需要精确关系的事实类问题，例如事件参与方、事件发生地点、事件之间的因果或顺承关系。

## 用户场景

1. 用户问“长平之战是哪个国家发起的”。
2. 用户问“长平之战和邯郸之战之间有什么关系”。
3. 用户问“某个地点出现在哪些战争中”。

## 输入与输出

- 输入：归一化后的实体列表、问题类型、朝代/战争类型筛选条件。
- 输出：结构化事实、关系三元组、1 跳邻居、路径数据，格式遵循 data-contract.md。

## GraphRAG 在本项目中的定义

本项目不使用 Microsoft GraphRAG 的“从零抽图 + 社区摘要”整套方案，因为知识图谱已经由旧项目抽取完成。

本项目的 GraphRAG 定义为“知识图谱增强检索”：

1. 旧图谱经过 F09 治理后形成干净图谱快照。
2. F02 先从用户问题中识别并归一实体。
3. F03 根据问题中的实体，在图谱快照中检索结构化事实。
4. 结构化事实作为证据进入 F05，与 F11/F04 的文本检索结果共同参与最终回答。

## GraphRAG 执行流程

```text
用户问题
    ↓
F02 实体识别与消歧
    ↓
在图谱快照中匹配标准实体
    ↓
判断问题类型并执行图谱查询
    ↓
返回结构化事实、关系三元组、子图或路径
    ↓
F05 与文本检索结果合并排序
```

具体步骤：

1. F09 生成预构建图谱快照文件，服务启动时加载为内存索引，不在请求阶段重新建图。
2. 用 F02 输出的标准实体名匹配图谱节点。
3. 按问题类型选择查询方式，映射规则见下节。
4. 图谱检索结果统一转换成三元组形式，例如“赤壁之战 - 发起方 - 曹操军队”。
5. 每条图谱事实保留关系类型、来源、置信度等元信息。
6. 如果实体不存在、实体孤立或问题类型不适合图谱查询，不返回虚构关系，改由文本检索和实体卡片处理。
7. 朝代、战争类型筛选条件作为图谱检索的过滤条件。
8. 图谱索引同时加载原始关系与**规则推理边**（快照目录内的 `inferred_relations.json`，
   P2 规则推理移植，字段口径见 [data-contract.md](../data-contract.md) 的“规则推理产物”节）：
   事件类问题因此能命中「隶属于战役 / 间接因果 / 连续演进」这类由 20 条规则推导出的关系，
   战役隶属、因果链等多跳问题不需要在线展开即可回答；推理边的证据带 `kg_inference` 与
   规则/溯源标记，引用标题标注来源规则，可回溯到原始关系行。

## 问题类型与图谱查询策略

| F02 问题类型 | F03 图谱查询策略 |
| --- | --- |
| single_entity | 查询实体属性、1 跳邻居，返回实体卡与直接关系 |
| relation | 查询事件或实体相关的组织、人物、地点关系 |
| event_event | 查询两个事件之间的直接关系或两跳路径 |
| comparison | 分别查询比较对象的一跳子图，不做强行合并 |
| timeline | 查询相关事件及时间字段，图谱只负责关系与事件锚点 |
| background | 图谱只返回实体基础上下文，主体交给文本检索 |
| unknown | 图谱对**主实体（首个命中实体）**执行 1 跳查询作为候选，不强推路径结果；多实体时其余实体由文本通道覆盖 |

支持的具体图谱查询：

1. 单实体介绍。
2. 事件-人物/组织/地点关系。
3. 事件-事件因果、顺承、包含、并列关系。
4. 多事件直接关系或两跳路径。
5. 地点参与的战争检索。

示例：

- “赤壁之战有哪些参战方”：匹配“赤壁之战”事件，查询其组织、人物关系。
- “长平之战和邯郸之战之间有什么关系”：匹配两个事件，查询 event_event 关系。
- “洛阳发生过哪些战争”：匹配“洛阳”地点，查询所有关联事件。
- “阪泉是什么”：如果“阪泉”孤立，则不执行关系路径检索，只返回实体信息和文本证据。

## 实现思路

1. RAG 子项目内置只读快照图谱，不依赖旧 Neo4j 服务。
2. 图谱以实体节点、关系边、属性构建内存索引或文件索引。
3. 关系边按事件关系表加载，保留关系类型、方向、来源、置信度。
4. 支持实体详情、关系、1 跳邻居、有限深度路径等查询。
5. 图谱检索结果带有来源和置信度，避免无中生有。
6. 孤立节点不进入路径逻辑，只由文本通道或实体卡片处理。
7. 孤立节点保留在数据快照中，不因缺少关系而删除。

## 图谱证据输出格式

每条图谱证据建议包含：

```text
subject: 源实体名称
subject_type: 事件/人物/组织/地点
relation: 关系类型
object: 目标实体名称
object_type: 目标实体类型
evidence: 证据原文或来源标识
confidence: 置信度
source_type: 结构化数据来源
```

例如：

```text
subject: 长平之战
subject_type: 事件
relation: 发起方
object: 秦军
object_type: 组织
evidence: 事件-组织关系表
confidence: high
```

该格式输出给 F05，再由 F05 统一合并文本证据并交给 F06 生成回答。统一字段定义以 data-contract.md 为准。

## 依赖与前置条件

1. 已经完成实体消歧与孤立节点标记，生成干净图谱快照（关系补边待人工审核回填，见 F09「人工审核要求」）。
2. F02 实体识别结果可以稳定匹配图谱节点。
3. 图谱检索结果格式可被 F05 证据融合模块使用。
4. 图谱快照带版本号，F03 与 F09/F11 索引使用同一数据版本。

## 验收标准

1. 已连通实体可以查询到正确关系。
2. 孤立节点不会导致系统返回虚构关系。
3. 图谱检索可以返回可直接展示的子图数据。

## 待确认问题说明

1. 图谱最大查询深度：指从问题实体出发，最多经过多少条关系边再返回结果。一跳只查直接邻居，
   两跳可以查出“事件 A 的地点又参与了哪些其他战争”这类间接关系。深度越大，检索越全，
   但噪音和耗时也越高。**该建议未采纳**：除 event_event 策略走两跳路径外，其余策略
   均按 1 跳邻接定档（深度经 F10 评测确认，见 `server/graph/search.py` 与
   `server/graph/query_strategies.py`）。
2. 图谱展示方式：知识面板默认展示一跳子图，关系型问题按需展示完整路径。展示完整路径可以让用户看清 A 到 B 的关系链，但复杂图谱会变拥挤。初版建议“子图默认一跳，路径展示上限两跳”，后续根据演示效果确认。**当前实现**：panel 子图 = 命中实体 + 1 跳邻居 + 融合证据两端实体（≤ 24 节点），不单独做“路径视图”；event_event 的两跳路径以三元组证据形式进入回答，其两端实体可在子图中呈现（见 F07 模块清单第 3 项）。
