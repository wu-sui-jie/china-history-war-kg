# F02 问题理解、实体识别与消歧

- 功能编号：F02
- 状态：已完成（RAGv2：词典/规则优先版；LLM 兜底开关预留）
- 创建时间：2026-09-03
- 实现说明：见 [RAG_v1/RAGv2-在线问答链路.md](../RAG_v1/RAGv2-在线问答链路.md)

## 功能作用

从用户问题中判定问题类型、识别事件/人物/组织/地点/朝代实体、处理多轮追问的指代问题，并把别名和古今地名归一到知识库标准实体，保证后续图谱检索和文本检索能够命中。

## 用户场景

1. 用户问“涿鹿之战发生在哪里”，系统应识别“涿鹿之战”事件。
2. 用户问“涿鹿和涿鹿县是不是同一个地方”，系统应能通过别名归一判断。
3. 用户没有写全名时，系统应尽量给出候选实体供检索使用。
4. 用户可以看到当前问题被识别成了哪些实体。
5. 用户识别结果错误时，可以手动纠正实体，纠正后重新发起检索。
6. 用户问“涿鹿之战发生在哪里”后继续问“它的结果如何”，系统能根据前文把“它”还原为“涿鹿之战”。

## 输入与输出

- 输入：用户问题文本、会话历史、筛选条件。
- 输出：问题类型、改写后问题、最终实体列表、候选实体列表、实体类型、归一化后的标准名称、朝代、置信度。

## 实现思路

1. 建立事件名、人物名、组织名、地点名、朝代名的词典。
2. 优先使用词典和规则进行快速匹配，例如“XXX之战”识别为事件。
3. 词典无法覆盖的问题再调用大模型进行实体识别。
4. 使用别名表和古今地名映射把“涿鹿之野”“涿鹿县”归一到标准实体。
5. 实体识别结果同时提供给图谱检索通道和文本检索通道。
6. 前端展示识别到的实体卡片或标签。
7. 前端提供手动纠正入口，用户可以新增、删除或替换错误实体。
8. 用户纠正实体后，系统按新实体重新执行检索与回答。
9. 根据问题句式、实体数量和关系词进行问题类型判定，例如单实体、关系、事件关系、比较、时间线、背景。
10. 大模型作为规则判定的补充，用于口语化和规则无法覆盖的问题。
11. 多轮追问时结合会话历史做指代消解，把“它”“他”“这场战争”等替换成完整实体名。
12. 输出改写后问题，供 F03 和 F04 使用，避免口语表达导致检索失败。
13. rewritten_question 由 F02 生成，用于后端内部路由，前端首轮不传该字段。
14. 用户纠正实体时，前端通过 corrected_entities 发起新请求，支持 add、replace、remove 三种操作。
15. 纠正重查携带上一轮会话历史，供 F02 对“它”“这场战争”等指代继续消解，字段定义见 data-contract.md。
16. 同一问题存在多个候选实体时，candidates 随 entities 一起输出，供前端实体卡展示和手动纠正。
17. remove 后问题不再包含任何实体时，entities 输出为空，请求按纯文本检索处理；无有效文本证据时由 F06 拒答。

## 问题类型分类

初版问题类型包括：

1. single_entity：介绍单个实体。
2. relation：查询关系或参与方。
3. event_event：查询事件之间的关系。
4. comparison：比较多个实体或事件。
5. timeline：查询时间顺序或时间线。
6. background：查询过程、原因、背景。
7. unknown：无法判定。

分类结果作为公共参数传给 F03、F04、F05。

## 筛选条件

F01 的朝代、战争类型筛选条件作为 F02 输入的一部分，输出时随实体和问题类型一起传给图谱检索与文本检索。

补充口径（2026-09-13 两轮修复后，终态）：

- **显式筛选（硬过滤）**：只有 F01 下拉传来的 filters 会真正过滤结果；
- **问句自动识别（软偏置）**：F02 还会从问句识别朝代（如"战国时期的长平之战"→
  `战国`；"鸣条之战与商朝的建立有什么关系"→`商`，含单字朝代 + 朝/国/代 后缀），
  但只写入 `F02Output.dynasty_bias`，**不剔除任何结果**。偏置的实际生效范围：
  - **图谱侧生效**：F03 在策略执行前重排命中节点，可经 `top_k` 截断影响证据集合；
  - **文本侧不生效（如实说明）**：F04 只是把命中朝代的片段前置在"检索返回序"里，
    随后 F05 按相关分（min-max 归一化、分各不同）重排，返回序被覆盖；即文本侧
    偏置目前不改变最终排序。若未来需要文本侧生效，可把偏置折进文本 `_score`
    （会改变融合排序，需重跑基线复核）。
- 为什么不做硬过滤：硬过滤会把"被问到的朝代"连同事件本身剔除——鸣条之战朝代为
  "夏"，问"与商朝的关系"时若把"商"当硬筛选，图谱/文本/融合全为 0、直接拒答
  （首轮评测中 B01/E01/R05/T03 四题即由此被误拒）。该机制与词典是否补别名无关：
  实测给词典补 `商朝→商` 后，若仍走硬过滤，E01 会再次被打回拒答。
- 回归守护：`tests/test_f02_regression.py`（四题不得拒答；补别名后仍不得拒答）、
  `tests/test_dynasty_filter.py`（识别语义）。
