# F04 文本检索通道

- 功能编号：F04
- 状态：已完成（RAGv5：关键词（FTS5/BM25）+ 向量（Chroma 余弦）+ hybrid 融合三模式可用，
  部署级开关 `TEXT_MODE` 默认 hybrid/rrf；评测结论：回答覆盖 71.7% → 85.1%、长改写 AND 失效被向量通道弥补）
- 创建时间：2026-09-03
- 实现说明：见 [RAG_v1/RAGv2-在线问答链路.md](../RAG_v1/RAGv2-在线问答链路.md)（RAGv2 关键词版）与
  [RAG_v1/RAGv5-开发说明.md](../RAG_v1/RAGv5-开发说明.md) §四.2/§四.3（RAGv5 向量与融合）

## 功能作用

从事件卡片、原文片段和关系证据中找回与问题相关的文本证据，用于补充图谱无法表达的背景、过程和细节。

## 用户场景

1. 用户问“赤壁之战是怎么进行的”。
2. 用户问“为什么要进行某场战争”。
3. 用户需要查看答案对应的原文依据。
4. 开发者需要通过评测决定最终使用哪种检索方式。

## 输入与输出

- 输入：改写后问题、问题类型、归一化后的实体信息、朝代/战争类型筛选条件。
- 输出：Top N 文本片段、片段类型、来源、分数、相关实体，字段遵循 data-contract.md。

## 实现思路

关键词取词模式（2026-09-13 补充，RAGv4/F10 引入）：`search_keyword` 支持
`keyword_mode` 参数——`and_or`（默认）、`and`（仅 AND，用于评测量化"长改写问题
AND 命中 0"的失效面）、`or`（仅 OR，观察兜底召回质量）。仅评测链路显式传入；
常规问答默认路径零变化。

`and_or` 的实际口径（`server/text/searcher.py`，RAGv5 §2.5-2）：
先取 AND 结果，**AND 命中不足 3 条时并入 OR 结果**（不是只在 AND 为空时才兜底）——
长改写问题的 AND 常只命中 1–2 个片段，旧口径会把 OR 里更相关的片段整批丢掉；
合并后统一去重、筛选与分数归一化。

1. F11 负责完成文本切分、关键词索引和向量索引构建，F04 不重复处理文本切分。
2. F04 直接消费 F11 生成的索引，运行阶段只负责检索。
3. 初版不预先决定“单一关键词检索”或“混合检索”哪一种更好（2026-09-13 已用 F10 定档
   hybrid/rrf，见下方"待确认问题说明"的结论）。
4. 同时准备关键词检索、向量检索、混合检索三种可切换模式，供后续评测对比。
5. 关键词检索使用中文分词后的 BM25 或 FTS5。
6. 向量检索使用 F11 构建好的向量索引。
7. 文本片段必须保留来源、原文、相关实体等元信息。
8. 最终选择哪一种模式，以 F10 数据评测结果为准，不在开发初期直接定死。
9. “命中关键词”只在关键词检索模式下返回，不作为向量检索的强制输出。
10. 筛选条件作为文本索引元数据过滤条件使用。
11. 不同检索模式的原始分数必须在各自模式内先做 min-max 归一化到 0 到 1 再输出，避免 BM25、向量分数和混合分数无法统一比较；具体规则见 data-contract.md。

## 依赖与前置条件

1. F11 已完成文本切分与索引构建。
2. F11 生成的关键词索引和向量索引可被 F04 读取。
3. 索引带版本号，F04 读取的索引与 F09 快照版本一致。

## 验收标准

1. 演示问题可以找回相关文本片段。
2. 每条结果都能追溯到来源。
3. 文本片段与图谱事实重叠时不会直接冲突。
4. 输出字段符合 data-contract.md，并可被 F05 直接消费。

## 待确认问题说明（已关闭）

   `TEXT_HYBRID_STRATEGY=rrf`（rrf 文本召回 97.0% 优于 weighted 95.2% / fallback 94.6%，
   fallback 等于没做融合）。部署级开关仍保留三模式可切换，默认按定档值运行。
