# F05 检索结果融合与重排

- 功能编号：F05
- 状态：已完成（RAGv2 服务版；panel 唯一装配方）
- 创建时间：2026-09-03
- 实现说明：见 [RAG_v1/RAGv2-在线问答链路.md](../RAG_v1/RAGv2-在线问答链路.md)

## 功能作用

把图谱检索和文本检索的结果合并成一个统一、有序、可去重的证据集合，供回答生成模块使用。
同时负责组装 F07 所需的 panel 数据，是 panel 事件的唯一后端装配方。

## 用户场景

该功能主要在后台运行，用户通过回答质量和引用准确性感知其效果。

## 输入与输出

- 输入：图谱检索结果、文本检索结果、问题实体、问题类型、筛选条件、F09 快照中的实体卡/时间/坐标数据。
- 输出：排序后的统一证据列表、引用编号、来源、置信度、冲突提示、panel 数据。

## 实现思路

1. 使用 data-contract.md 中的统一证据结构，区分图谱事实、原始文本、事件卡片、关系证据。
2. 根据问题类型调整权重：关系问题提高图谱权重，背景问题提高文本权重。
3. 对重复实体和重复内容进行去重。
4. 初版只做结构化冲突判定，范围限定为图谱三元组之间同 subject、同 relation、不同 object
   （**different_object 仅对单值关系生效**：只判定 field_map 中 exact 单值组如发起方/防守方；
   主帅/将领等多值关系是并列事实行，多个 object 不报冲突，避免误报——实现见
   `server/fusion/conflict.py`），以及图谱三元组与事件卡片结构化字段不一致；
   raw_text 不参与自动冲突判定。
5. 最终把证据列表组装成可 JSON 化、可追溯的上下文。
6. 为最终进入提示词的证据统一分配 citation_index。
7. 组装 panel 数据，subgraph 的 nodes/edges 只在此处生成一次，panel 是 subgraph 的唯一输出来源。
8. timeline 按朝代分组、组内按可解析的 start_date 升序排序（起讫年份需从
   "前2179年 / 公元前26世纪"等文本解析，无法解析的条目保持数据原序并置于组内末尾），
   时间不详的条目归入“时间不详/仅知朝代”分组置尾；map_points 只保留有坐标地点。
9. field_vs_triple 冲突使用 F09 输出的关系-事件卡片字段映射表。

## 依赖与前置条件

1. 图谱检索和文本检索均有可用输出。
2. 证据结构符合 data-contract.md。
3. 图谱结果与文本结果均携带来源和版本号。
4. 可以从 F09 快照读取实体卡、时间和坐标数据。

## 验收标准

1. 同一问题不会重复返回大量相同内容。
2. 关系型问题优先命中图谱证据。
3. 答案中的引用编号可以对应到具体证据。
4. 冲突证据被保留并传递给 F06，不会因简单规则被误删。
5. panel 数据由 F05 输出，F07 只读 panel，不再自行拼接第二套 subgraph。

## 待确认问题说明

1. 图谱证据和文本证据冲突时怎么处理：
   - 初版策略已经确定为“结构化冲突才输出 conflicts，文本证据不参与自动冲突判定，冲突证据全部保留”，F06 不擅自裁决。
   - 是否引入优先级投票等机制，等 F10 出现真实冲突案例后再微调。
2. 是否引入独立排序模型：
   - 独立排序模型会对初检结果再次打分，通常能提升排序质量，但会增加模型依赖、部署复杂度和耗时。
   - 也可以先使用规则融合和来源权重排序，等 F10 评测说明有提升空间后再决定是否引入。
   - 该问题建议作为可配置项保留，不强制二选一。
