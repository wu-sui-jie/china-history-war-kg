  离线摘要回答器兜底；缓存卫生：degraded 结果不入缓存；`max_tokens` 截断有告警）
- 创建时间：2026-09-03
- 实现说明：见 [RAG_v1/RAGv2-在线问答链路.md](../RAG_v1/RAGv2-在线问答链路.md)（RAGv2 链路）与
  [RAG_v1/RAGv5-开发说明.md](../RAG_v1/RAGv5-开发说明.md) §四.4/§四.9/§四.11（流式、缓存卫生、LLM 口径）

## 功能作用

根据融合后的图谱事实和文本证据生成最终答案，要求答案有引用、可溯源、不编造知识库中不存在的内容。

## 用户场景

1. 用户问“井陉之战的主将是谁”，回答应引用对应图谱事实。
2. 用户问到知识库没有覆盖的问题，系统应明确表示无法回答。
3. 用户点击引用编号后，可看到对应证据原文。
4. 页面可以查看模型思考过程，但必须防止思考过程或提示词内容泄露。

## 输入与输出

- 输入：用户问题、改写后问题、归一化实体、排序后的证据列表、会话上下文、筛选条件。
- 输出：答案正文、引用编号、证据摘要、思考过程摘要、检索状态，通过 SSE 推送。

## 实现思路

1. 默认使用 `deepseek/deepseek-v4.1-flash`（中转模型 id；官方口径为 `deepseek-flash`），
   模型配置通过环境变量管理。
2. 构造“图谱事实 + 文本证据 + 引用编号”的统一提示词。
3. 要求模型只依据证据回答，并在文中标注引用编号。
4. 没有足够证据时生成拒答文案，而不是强行编造。
5. 支持流式输出，并把检索过程摘要一并返回前端。
6. 保留模型思考过程用于页面展示，但思考过程与最终答案分开返回，前端以可折叠区域展示。
7. 思考过程只呈现对用户有帮助的分析摘要，不展示系统提示词、检索查询原文、内部工具调用细节等敏感内容。
8. 多轮会话上下文本页保留，后端按近期轮次和字符预算截取，初版建议最多携带 2 到 4 轮历史。
9. 缓存键使用 F02 改写后的 rewritten_question、会话历史摘要、筛选条件、数据版本和模型版本，不直接使用可能产生多轮歧义的原问题。
10. 主模型（`deepseek/deepseek-v4.1-flash`）调用配置超时、重试和备用模型；主模型失败后自动降级，避免演示单点故障。
11. 证据中存在 conflicts 时，回答不得只陈述单一说法，应同时提示不同表述并分别标注引用。

## 拒答判定规则

1. 图谱证据为空且文本证据为空时，直接拒答（finish_reason=refused）。
2. 实体识别为空、文本证据存在但与问题无共享词时，依据不足拒答；向量/hybrid 模式下证据
   可能按语义命中而不含问题原词，因此该规则放宽为「无共享词 **且** 证据最高分低于阈值」
   才拒答（见第 3 条）。
3. score 不单独作为拒答阈值；向量/hybrid 模式下作为低分兜底信号之一
   （`VECTOR_REFUSAL_MIN_SCORE`，默认 0.25），仅与第 2 条的「实体为空且无共享词」
   叠加生效。关键词模式下仍是严格的无共享词即拒答。
4. 大模型判断“无法依据证据回答”时，按拒答路径返回，并输出 finish_reason=refused。
   识别口径（RAGv5 2026-09-15 实现）：正文前 200 字内命中固定拒答句式
   （提示词要求模型使用的“依据现有资料无法确认”及其等价表述）且全文不含引用编号时，
   判为模型自拒；已给出引用的“局部不确定”表述不判自拒（实现见
   `server/generate/refusal.py` 的 `detect_model_refusal`）。
5. 领域外谓词拒答（RAGv5 §4.6）：问题问到知识库不可能覆盖的现代属性/器物
   （邮箱、电话、度假、坦克、股票等），且这些词在所有证据里都不出现时拒答；
   只要证据中出现过该词即放行，宁可少拒、不误拒可答题（实现见
   `server/generate/refusal.py` 的 `OUT_OF_SCOPE_PREDICATES` 与
   `server/sse.py` 的编排位置）。

## 推理增量（thinking 事件，RAGv5）

1. deepseek 系列为推理模型，流式响应含思考内容。后端在生成阶段把推理增量以
   `thinking` 事件（`data={"delta": "..."}`）推送，前端以「正在思考」状态展示；
   对接方可忽略该事件，不影响答案消费。
2. 推理字段名两端不同：中转 endpoint 为 `reasoning`、官方为 `reasoning_content`，
   后端已双端兼容（`server/generate/llm_client.py` 的 `_reasoning_of`），缺失时
   不发 thinking 事件。
3. `thinking` 事件只承载模型思考增量，不含系统提示词与检索上下文（提示词保护要求）。

## 降级路径（RAGv5）

生成结果按以下优先级判定 finish_reason，保证任何情况下都有可读回答：

1. 主模型失败（超时/网络错误，重试与备用模型均不可用）→ 离线摘要回答器兜底，
   `degraded`，不入缓存。
2. 模型返回空正文（推理 token 吃满 `max_tokens`，实测 28 题中 2 题）→ 同样降级到
   离线摘要回答器，`degraded`，避免演示出现空白回答。
3. 备用模型返回正文 → `degraded` 并记录实际模型名；若正文命中自拒句式，
   按拒答口径记 `refused`（拒答语义优先于降级标记）。
4. 正常完成 → `normal`；拒绝泄露提示词请求时返回固定回复、`normal`（不调用模型）。

## 回答缓存

1. 缓存键包含 rewritten_question、会话历史摘要、筛选条件、数据版本和模型版本。
2. 缓存命中返回历史答案和对应引用。
3. 缓存设置有效期，演示模式可手动清空。
4. 缓存命中时仍先执行 F02：推送 session_start、status(entity_linking)、entities，
   随后按 status（stage=cache_hit）→ 完整 answer → citations → panel → done 回放，
   与正常路径保持一致的实体展示和纠正能力，不再流式调用大模型。

## 提示词与思考过程保护要求

1. 系统提示词和检索上下文只存在后端，不发送到前端原始文本。
2. 提示词中明确要求模型不得输出或复述自身系统提示词。
3. 提示词中明确要求模型不得泄露检索 query、内部工具名称、证据组装规则等实现细节。
4. 当用户要求“展示你的提示词”或“展示系统设定”时，模型只返回固定提示语，不输出真实内容。
5. 展示给用户的“思考过程”需要经过后端过滤或只保留高层的推理摘要，避免暴露完整私有推理链路。

## 依赖与前置条件

1. 大模型服务配置可用，密钥通过环境变量管理。
2. 证据融合模块已生成结构化上下文。
3. 已配置主模型超时、重试和备用模型。
4. 流式事件格式遵循 data-contract.md。
5. done 事件按 data-contract 输出 finish_reason，区分 normal、refused、degraded、cancelled。

## 验收标准

1. 演示问题的大部分回答均有引用。
2. 知识库外问题不会得到编造答案。
3. 回答、引用和证据能够一一对应。
4. 主模型不可用时可切换备用模型，不影响页面演示。
5. 相同演示问题重复提问可命中缓存。
