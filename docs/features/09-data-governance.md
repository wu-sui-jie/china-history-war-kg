# F09 数据快照与知识库治理

- 功能编号：F09
- 状态：已完成（RAGv1 交付：基础快照治理、事件卡片结构化字段、关系-卡片字段映射表、data_issues 前后明细）
- 创建时间：2026-09-03

## 功能作用

从旧项目只读导出 RAG 所需数据，完成实体消歧、孤立节点处理、关系补边和干净图谱索引构建，为问答系统提供干净、可追溯、可人工审核的数据底座。

## 用户场景

该功能属于离线数据流程，用户不直接使用，但其质量决定问答效果。

## 数据快照说明

数据快照是从旧项目只读导出的固定数据副本，包含 RAG 问答运行所需的原始文本、实体、关系、事件卡片、证据片段和图谱索引结果；文本索引由 F11 后续构建。

生成快照后，RAG 后端只读取自己的数据快照，不再依赖旧项目数据库或旧服务是否启动。

快照内容建议包括：

1. 旧项目原始正文文本。
2. 事件、地点、人物、组织四类实体数据。
3. 事件-地点、事件-人物、事件-组织、事件-事件关系数据。
4. 事件卡片、原文引用、关系证据等文本语料。
5. 处理后的干净图谱索引；原始正文和结构化文本语料交由 F11 继续做切分与文本索引。
6. 标准化实体词典、别名表、朝代别名和现代地名映射。
7. 标准化战争类型词典与事件类型映射表。
8. 治理版本号与版本清单，供 F03、F11 和数据契约统一引用。
9. 关系类型到事件卡片字段的映射表，供 F05 做 field_vs_triple 冲突判定。

## 输入与输出

- 输入：旧项目原始文本、旧项目抽取结果、旧 SQLite 数据、别名配置。
- 输出：RAG 数据快照、干净图谱索引、文本语料、实体词典、别名表、治理报告、版本清单。

## 实现思路

1. 新 RAG 目录内编写只读导出脚本，不修改旧代码。
2. 把事件、地点、人物、组织、关系导出为统一快照。
3. 实体消歧采用名称归一、别名映射、候选相似度匹配等方法，优先保留低风险自动合并。
4. 对“涿鹿”和“涿鹿县”等已知别名建立映射，不直接删除原始记录。
5. 对孤立节点进行统计、归类和补边，补边候选记录来源与置信度，不自动视为高置信度事实。
6. 补边来源可以是事件文本字段、证据片段或定向关系抽取；高风险补边标为 pending_review。
7. 对实体合并结果和新增关系执行人工抽检，抽检记录写入治理报告。
8. 生成供图谱检索使用的干净图谱索引，并把文本语料交给 F11 构建文本索引。
9. 输出治理报告，记录孤立节点数量、重复名称数量、关系覆盖率、抽检结果和治理前后对比。
10. 每次治理生成新版本号，避免旧索引引用旧数据。

## 战争类型字段来源

1. 旧项目 events 表已存在 event_type 字段，当前覆盖 27 类，无空值。
2. F09 对旧事件类型做归一化，例如同义写法合并，并生成标准战争类型词典。
3. 图谱节点、事件卡片和文本片段在快照中记录归一化后的 event_type。
4. F01 的战争类型筛选使用该词典，不再使用前端自由输入。
5. 治理报告输出战争类型分布和未分类数量，作为筛选功能的数据依据。

## 人工审核要求

1. 实体合并、别名建立和候选补边默认标记为待审核或低置信度。
2. 自动结果必须先人工抽检，再进入高置信度图谱。
3. 人工抽检至少覆盖：高风险补边、重复实体合并、事件名称歧义、地名别名。
4. 战争类型归一化映射表必须经过人工确认，映射错误会导致整批事件无法被正确筛选。
5. 每条审核记录保存操作人、处理前内容、处理后内容和审核结论。

## 孤立节点处理策略

1. 孤立节点全部保留，不执行删除。
2. 能补边的孤立节点补候选边，并记录来源与置信度。
3. 不能补边的孤立节点保留为文本实体或孤立实体标记。
4. 孤立节点可以参与文本检索和实体介绍，不参与图谱路径检索。
5. 标记为 pending_review 的候选边不进入 F03 可查询图谱，只保留在治理报告中等待人工审核。

## 依赖与前置条件

1. 旧项目数据文件可只读访问。
2. F11 从本功能输出的文本语料继续执行切分与索引构建。
3. 治理过程需要人工审核流程参与，不能完全自动发布。

## 验收标准

1. RAG 运行时不依赖旧服务是否启动。
2. 治理报告包含治理前后对比。
3. 数据来源、证据和置信度可以追溯。
4. 孤立节点全部保留，不因缺少关系而删除。
5. 人工审核记录存在，候选补边不会直接冒充高置信度事实。
6. 治理报告和索引都带版本号。
7. 战争类型词典与事件类型映射已生成，F01/F03/F04 可读取。

## 项目代码托管约定

1. 整个项目代码包含旧代码与 RAG 子项目，后续提交到新建的 GitHub 公开仓库。
2. 不再推送到 debug-debug-backup 旧仓库。
3. 数据快照是否随 Git 提交，需要根据仓库大小和数据来源授权情况后续确认。
