# F11 文本切分与索引构建

- 功能编号：F11
- 状态：已完成（RAGv1 交付切分 + FTS5；**RAGv5 补齐向量索引**：百炼 text-embedding-v4 + Chroma
  持久化集合，9,544 条 / 1024 维；关系证据按事件卡片补齐 `event_type` 元数据）
- 创建时间：2026-09-03
- 实现说明：见 [../CHANGELOG.md](../CHANGELOG.md)（切分与关键词索引、向量构建链）与 [../data-contract.md](../data-contract.md)

## 功能作用

把原始正文、事件卡片和证据片段统一切分成适合检索的文本片段，并构建关键词索引和向量索引，为 F04 文本检索提供可直接查询的向量数据库。

## 用户场景

该功能属于离线数据流程，用户不直接使用，但它是文本 RAG 能够运行的前提。

## 输入与输出

- 输入：F09 输出的文本语料、向量模型配置、切分参数。
- 输出：文本片段表、片段元信息、关键词索引、向量索引、索引版本清单、索引构建报告。

## 文本切片数据源

F11 使用以下三类文本数据，三类数据全部切片入库：

1. 原始正文：旧项目中的战争史原文，用于回答背景、过程和详细描述类问题。
2. 事件卡片：以事件为单位整理出的结构化描述，包含事件名、朝代、时间、参与方、结果、影响等信息。
3. 证据片段：关系证据、引用原文和来源片段，用于回答需要精确引用和溯源的问题。

每个文本片段都标记片段类型，例如 raw、event_card、evidence，方便后续检索、融合和引用展示。

原始正文和事件卡片之间存在内容重叠属于正常现象。检索阶段通过片段类型、来源和排序策略共同控制，不要求物理去重后只保留其中一种。

## 实现思路

1. 读取原始正文、事件卡片、证据片段、地点/人物/组织描述等文本语料。
2. 事件卡片以“事件”为最小单元，原文和证据按内容边界切分。
3. 每条片段保留片段类型、事件名、事件类型、来源、朝代、时间、相关实体等元信息。
4. 对过长的文本按句子边界二次切分，并保留前后重叠，避免切分截断关键信息。
5. 每个片段都需要能回溯到原文档、原事件、原证据和来源。
6. 使用云端中文文本向量模型生成片段向量。
7. 把向量和元数据写入本地向量数据库或向量文件，构建向量索引。
8. 同时建立关键词索引，例如中文分词后的 BM25 或 SQLite FTS5。
9. 输出索引构建报告，记录片段数量、向量数量、切分参数、缺失文本数量。
10. 每次构建生成新索引版本号，片段 ID 与 F09 数据版本对应。

## 向量模型

1. 已确认使用云端中文文本向量模型。
2. 向量模型接口和具体模型名通过配置文件管理，密钥使用环境变量。
3. 云端接口不可用时，可以在演示环境配置降级向量服务，不改变现有索引结构。

## 向量数据库选型

初版建议优先选择轻量、可本地运行的方案，避免现场演示依赖重型服务。

可选方案：

1. 本地向量文件 + 内存检索：适合数据量较小的演示版本。
2. SQLite + 向量扩展：部署简单，适合单机运行。
3. Qdrant 等独立向量库：效果和扩展性更好，但需要额外服务。

具体选型结合数据量和现场环境确认，不在文档中提前固定。

## 文本切分规则

1. 原始正文和事件卡片同时切分，证据片段单独保留为可引用的短文本。
2. 事件卡片优先按事件边界切分，原文优先按章节、段落和句子边界切分。
3. 超长文本设置最大长度，超过后按句号、分号等句子边界切分。
4. 相邻片段保留少量重叠，降低跨片段信息丢失风险。
5. 片段中保留片段类型、事件名、事件类型、朝代、时间、相关实体、来源字段；原始正文没有归一化事件类型时不强制填充。

## 依赖与前置条件

1. F09 已生成文本语料快照。
2. 云端向量模型接口可用。
3. 已确定向量数据库或索引存储方案。

## 验收标准

1. 文本切分后没有无法回溯来源的片段。
2. 向量索引和关键词索引可以正常生成。
3. F04 可以读取索引完成检索。
4. 索引构建报告记录完整切分参数和构建数量。
5. 索引带版本号，F04 能确认其与 F09 快照版本一致。

## 已确认需求

1. 使用云端文本向量模型。
2. 原始正文、事件卡片、证据片段全部进行切分和索引构建。
3. 使用原文建库前，需确认数据来源授权或使用已授权文本。
