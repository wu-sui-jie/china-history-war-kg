## 三、清单外的顺带修复

这些不在工作单里，是改到相关文件时发现的真实缺陷：

1. **旧前端类型检查此前完全不可用**：项目锁 TypeScript 4.9，而 Vue 3.5 的 `.d.ts` 需要 TS 5.x（`NoInfer`、`ToggleEvent` 未定义），`vue-tsc` 还会对四个无 `lang="ts"` 的维护页报 TS6504。处理：`typescript` → `^5.4.5`、`vue-tsc` → `^2.0.29`（**运行时行为不变**，vite 用 esbuild 转译）、`tsconfig.json` 开 `skipLibCheck` 与 `allowJs`，然后把暴露出来的 51 条错误逐条修到 0（`KgGraph.vue` 的 echarts 相关类型注解、`store/user.ts` 的 `never[]` 推断、`markdown-it` 缺 `@types`、`error` 的 `unknown` 收窄等）。
2. **`lay-textarea` 的自适应失效**：写了 `:autosize="{minRows: 1, maxRows: 2}"`，而组件类型与实现用的是 `minRow`/`maxRow`（单数），原写法不生效。已改正。
3. **`lay-avatar` 的 `size="40px"` 非法**：组件 `size` 只接受 `xs/sm/md/lg`，原值被忽略、头像按默认尺寸渲染。改为用 CSS 固定 40px（视觉与作者意图一致）。
4. **`lay-button type="text"` 非法**：`ButtonType` 只有 `primary/normal/warm/danger`，改为 `normal`（原本落到默认样式，视觉不变）。
5. **`lay-checkbox` 缺必填 `value`**：`TimelineView` 的「只看时间异常」补上 `value`。
6. **`model_search.get_nodes_by_type` 等缺少异常兜底**：非法标签现在抛 `ValueError`，由路由的 `except` 转成明确错误而不是 500 堆栈。

## 六、需要人工执行或确认的事项

1. **轮换历史泄露的凭据（P0-1，部署前必做）**
   - Neo4j：`ALTER USER neo4j SET PASSWORD '<新口令>'`，同步更新 `backend/.env` 的 `NEO4J_PASSWORD`；
   - JWT：换一个全新的 `JWT_SECRET`（`openssl rand -base64 48`），换掉后所有旧 token 立即失效；
   - **本机 `backend/.env` 目前仍是历史口令**，本轮没有替换——擅自改会让本地 Neo4j 连不上。
   - 彻底方案 `git filter-repo` 重写历史会改变全部提交哈希，另行决策。
2. **真实环境端到端验证**：本机未跑 Neo4j 与 Ollama，图谱写入链路（含新的 `--yes` 导入与对账）、旧版问答链路、以及前端关键页面（401 跳转、`viewer` 被拒写、RAG iframe）需要在真实环境走一遍。
3. **首次登录须知**：新注册账号是 `viewer`（只读），需要写权限时用 SQL 提权：
   `UPDATE UserInfo SET role = 'editor' WHERE account = '...';`。存量账号已在启动迁移中回填为 `admin`。
4. **局域网访问**：前端从别的机器访问时，需要把来源加进 `CORS_ALLOW_ORIGINS`（默认只放行本机 `:3001`）。
5. **前端依赖安装**：`package.json` 增加了 `dompurify`、移动了 `mockjs`、升级了 `typescript`/`vue-tsc`，其他开发机需要重新 `pnpm install`。
6. **旧前端产物需重建**：本轮改了 `src/`，部署到服务器时要用新的 `dist/`（`pnpm build`，vite `base=/static/`）。

## 七、遗留风险

- **RAG 仍无自身鉴权**：本轮只加了安全响应头与路径脱敏，`/api/query` 依然是公开接口。公网部署前必须在 nginx 打开 `auth_basic`（或换 `auth_request` 接 SSO），否则任何人都能耗你的模型额度。
- **前端鉴权仍是「前端守卫 + 后端 401」双保险**：路径绕过前端守卫直接调接口仍会被后端 401 拦住，但前端隐藏菜单不等于权限控制，不要在文档里把它描述成访问控制手段。
- **`sync_status=failed` 只做可见化，未做补偿**：对账能把差异暴露出来，但没有自动重试或补偿队列，出现不一致仍需人工跑 `sync_sqlite_to_neo4j.py`。
- **mockjs 只在开发态**意味着开发时的菜单来自 mock 数据、与后端菜单可能不一致，加菜单项仍要改三处（已写进 frontend README）。
- **类型检查首次可用**：`strict: true` 下仍有大量 `any`，本轮只保证「0 错误」，不代表类型模型准确；`FE-7` 的「渐进补类型」仍需继续。
