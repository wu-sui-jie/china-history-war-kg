## 一、高危（4 项，全部闭环）

### H1 登出/会话过期时问答历史泄入全局 key（前端）

- **链路**：`BasicLayout.logOut()` 与 `api/http.ts` 的 `handleUnauthorized()` 都是**先**
  `clearSession()`（userInfo 置空）**再**跳登录页；页面随路由切换卸载，`onBeforeUnmount` 里
  `saveChatHistory()` 此刻读 `userStore.userInfo?.id` 只能拿到 `undefined`，key 退回全局
  `chatHistory`——离开的那个账号的**整份**历史被复制进公共桶，之后任何账号都能读到。
- **改法**：页面在挂载时把本页所属的账号 id **钉住**（`scopedUid`），落盘只用它，不再实时读
  `userStore.userInfo`。落盘去向因此与"清凭据的先后顺序"解耦。
  另加一条 fail-closed：**已登录但拿不到账号 id**（token 在、`userinfo` 未返回或失败）时
  既不读也不写公共桶——那份数据不知道属于谁，读会显示别人的记录，写会污染别人的桶；
  未登录（独立使用该页面）仍沿用全局 key，与改造前一致。
  同一处接缝在 `TextEntityExtract.vue`（识别记录）上按同样方式改掉。
- **用例**：`frontend/tests/component/inference-scope.test.ts`，走真实顺序
  （`clearSession()` → `unmount()`），断言"落进原账号的桶、公共桶是空的"。
  **反向验证过**：把修复回退后该用例失败（2/3 失败），修复后 3/3 通过。

### H2 legacy 回落把旧全局记录"收编"进先到者的账号桶（RAG）

- **链路**：`stores/session.ts` 的 `readPersisted()` 固定读
  `[账号桶, ...LEGACY_STORAGE_KEYS]`。uid 桶为空的新登录者会读到升级前的全局记录，
  下一次 persist 就把它写进自己的桶——与主应用侧"老全局记录归档、不归属任何账号"的策略矛盾；
  数据损坏时 `quarantine()` 还会把全局共享的原值删掉。
- **改法**：`persistedKeys()` —— **uid 非空时只读账号桶**，legacy 回落仅限无 uid（独立访问 :8000）。
- **用例**：`RAG/frontend/tests/unit/session-user-scope.test.ts` 新增"账号桶为空时不收编 legacy
  全局记录（也不能把它删掉）"与"独立访问仍回落 legacy"。**反向验证过**：回退修复后前者失败。

### H3 主前端 CI 漏掉整个 tests/unit 目录

- **改法**：`frontend/package.json` 补 `test:unit` 脚本；`ci.yml` 的 `legacy-frontend` job 在
  组件测试之前加跑 `pnpm run test:unit`（vitest 的 include 是 `tests/**/*.test.ts`，两条合起来
  即全量）。原先 `router-guard`（12 例）、`user-scoped-storage`（8 例）、`inference-render`
  （16 例）都不在门禁内。

### H4 "22 项验证"不可复现，backend 零常驻测试

- **改法**：新增 `backend/tests/` 常驻 pytest（**32 例**，4 秒跑完）与 `backend/pytest.ini`：
  - `test_admin_users.py`（10 例）：非 admin 一律 403、不能改自己、角色白名单、用户不存在 404、
    账号已删/伪造 token 立刻失效（实时查库 fail-closed）、列表不下发口令、改角色落库；
  - `test_menu_trim.py`（6 例）：admin/editor/viewer 三级裁剪、未知角色 fail-closed、
    空角色历史账号按 viewer 且与用户列表同口径；
  - `test_privilege_chain.py`（5 例）：注册只建 viewer（请求体塞 role 也无效）、viewer 写接口 403 /
    editor 放行、提权与降权对**同一 token** 立刻生效、旧问答接口限 editor；
  - `test_extract_endpoint.py`（11 例）：编排层全失败抛 `ExtractionUnavailable`、部分失败带
    `partial_errors`、接口 5xx/400 与响应体 code 一致、异常字符串不回显内部细节、被拦请求不触达模型。
- **两个替身**（写在 `tests/conftest.py`，导入 `app` 之前装好）：
  ① `py2neo.Graph` 打桩——`app` 导入时会构造 `neo4j_db()` 并测连接，CI 没有 Neo4j；
  ② 把 `SQLALCHEMY_DATABASE_URI` 指到临时文件——`app.py` 在模块级写死了 `backend/database`
  （本机那个 13MB 真实库，且被 .gitignore），Flask-SQLAlchemy 3.x 的 `init_app` 之后不接受改库，
  所以只能包装 `init_app`（详见 conftest 文件头）。
- **不打真模型**：所有会触达 LLM 的用例都换成假客户端/假编排器。首版有一例让
  `/api/extract/entities-events` 真跑下去，**本机挂着 Ollama 时直接卡住**（实测），已改为打桩，
  整套用例从 138 秒降到 4 秒。
- **CI**：`legacy-backend` job 增加"安装旧后端运行依赖（根 requirements.txt + pytest）"与
  `working-directory: backend` 的 `python -m pytest tests -q`。之前该 job 刻意不装依赖，
  现在要真跑用例就必须装。

## 三、低危打磨

**前端**

- 路由守卫注释改成与 persist 配置一致（userInfo **会**持久化，但"拿不到角色"在刷新/换号瞬间
  仍会发生，所以按需拉取不能省）；
- 被拦文案不再自称"数据运营页面"（文本实体识别不属于该组），改为"当前账号权限不足，无法访问该页面"；
- `RagAssistant.vue`：首次解析出账号不再重建 iframe（原先无条件 `reloadFrame()`，进页面白加载一遍），
  改为补发一次身份消息；只有真正换号才重建；
- `store/user.ts` 菜单白名单删掉死项 `/workspace/repair`（后端从不下发它，留着让人误以为入口存在）。

**后端**

- `DbUtil.get_role` 空值兜底由 `admin` 改 `viewer`（迁移已回填；兜底只剩风险：一次写库遗漏就是静默提权），
  `UserInfo.to_dict()` 同步改成 `viewer`——否则用户管理页会把空角色账号显示成"管理员"而接口按 viewer 放行；
- `initialize_entity_extractor` 改为在鉴权钩子**之后**注册（Flask 按注册顺序执行 before_request，
  前一个返回响应即短路）：原先未登录请求也会触发实体提取器/规则引擎的进程内单例构建；
- 改角色日志补旧角色（提权/降权的审计价值在"从什么变成了什么"）；
- 抽取接口的异常文案只回第一行并截断（`common_utils.brief_error`），完整内容进日志；
- `/api/extract/*` 的 `get_json(silent=True)`：畸形 JSON 返回 JSON 错误体，而不是 Flask 的 HTML 400 页。

**RAG**

- `normalizeUid()`：uid 必须匹配 `[A-Za-z0-9_-]{1,64}`，否则按"没有账号"处理。
  原先对象或超长字符串会被拼成 `:u[object Object]` 这种谁都不是的桶；`storageKeyFor` /
  `setActiveUid` / `parseUserScopeMessage` / store 的 `normalizeScopeUid` 统一走它（口径不一致会让
  "内存来自哪个桶"与"读写哪个 key"对不上）；
- 身份桥**回调成功后才推进去重位**：原先先推进再回调，回调抛错（换桶要读存储）时这个 uid 再也不会
  被通知，store 永远停在上一个桶且没有自愈机会；
- "首条身份消息到达前落全局桶"保持现状（审核认定为行为取舍，知悉即可）。
