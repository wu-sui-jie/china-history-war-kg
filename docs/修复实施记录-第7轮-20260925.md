**样式（这次拆分真正的难点，也是工作单第 4 条需要修正的地方）**：工作单写"样式已外移，
子组件需要的样式按 class 原样引用即可，**不要搬动**"——但 `index.css` 是由父组件
`<style scoped>` 提供的，而 scoped 只会给**父模板**的元素打 `data-v` 属性，子组件内部的元素
匹配不到：不处理必然掉样式。反过来直接去掉 `scoped` 也不行——实测有 9 个 class 与别的页面重名
（`clear-button`/`hint`/`sidebar-header`/`empty-text`/`kg-graph`… 见 TextEntityExtract 等页面），
全局化会污染它们。

采用的第三条路：**按页面根元素命名空间生效**——给 `index.css` 的每条选择器加 `.inference-container `
前缀（已提到该根元素的 3 条根规则保持原样）。效果等价于"手写版 scoped"，规则内容与先后顺序一字不动
（层叠关系不变），也不影响其它页面。迁移脚本 `frontend/scripts/namespace-inference-css.mjs` 自带
**等价校验**（写回前把加过的前缀去掉与原文逐字比对，不一致就中止、不写回）。

配套两个护栏脚本：

- `scripts/check-inference-style-coverage.mjs`：检查页面与四个子组件模板里的 class 是否都有样式兜底
  （拆组件最容易出的事故就是"某个 class 没人管了"）；两个从未定义过样式的结构标记
  （`kg-empty` / `kg-content-formatted`，与迁移前的 CSS 逐条核对过）在脚本里列了白名单并注明原因。
- `scripts/smoke-inference-page.mjs`：浏览器冒烟（桩后端托管 `dist/` + Playwright），断言的是
  **计算样式与交互结果**：侧边栏宽度 230px、用户气泡背景色、SSE 流式回答与 Markdown、思考过程、
  图谱展开/收起、实体卡片、新建会话回到空态、按账号落盘。

**这个冒烟当场抓到一个真回归**：重构时漏了 `isFirstLoad` 的复位（原逻辑藏在
`loadChatHistory` 的 setTimeout 里），空会话一直停在"正在加载聊天记录"、看不到常用提示与快捷提示。
类型检查与 133 个单测都发现不了——只有真浏览器 + 真产物能看出来。修复后复跑 17 项全过。

## 七、本轮顺带发现（均未擅自改，留给决策）

1. **EER 评估同输入不可复现**（方法学问题，建议优先处理）：`python evaluate.py` 用**完全相同的**
   pred / gold / config 连跑两次，关系抽取的 tp/fp/fn 与 F1 就不同（实测 `filtered_pred` 890 vs 888、
   关系 F1 0.739 vs 0.750、gold 1110 vs 1099 之外还有若干计数差）。据此核对第 5 轮的重跑结果时
   也发现同样的漂移。初步判断是模糊匹配在相似度并列时按集合/字典迭代顺序取贪心解，而字符串哈希
   每进程随机（PYTHONHASHSEED）。**这直接影响"用评估数字支撑学术结论"的可信度**，修法是让匹配
   定序确定化（并列时用稳定键打破），而不是设 PYTHONHASHSEED 掩盖。已记进[清单](项目审查与修复清单.md)
   的 EER 系列待办。
2. **RAG 构建模式标记写死路径**（W4 已修）暴露的同类隐患：文档里"两种构建互相覆盖"的坑还在
   （`npm run build` 会覆盖并入模式产物），目前只靠文档提醒，没有构建产物防呆。
3. **EER 的 `war_extraction/geocoding/__init__.py` 导入不存在的模块**（`review_geocoding`，
   目录里没有该文件）——只在显式 `import war_extraction.geocoding` 时才炸，本轮未动（属 EER 系列待办）。
4. 工作单第四节说 W3/W5 "建议独立分支做"：本轮 W3 在 main 上直接做，理由是行为不变性有
   67 请求快照逐字段对照兜底（比分支更硬的证据）；W5 改动面虽大但同样是"只改 import 与包名"，
