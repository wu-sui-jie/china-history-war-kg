### 2.2 四类部署阻塞问题的逐条验证

用 `deploy/scripts/verify_deploy_auth.py`（真机运行，用真实密钥签 token，不打印任何密钥）：

| 问题 | 实测结果 |
| --- | --- |
| **登录限流时钟** | 限流状态列已改 UTC epoch（`login_attempts` 表 12 列结构在快照里可见）；限流响应为 `HTTP 429 + {"code":429,"msg":"尝试过于频繁，请稍后再试"}` |
| **RAG token 撤销** | 内部接口三态：有效 token → `active=true`；**已删号账号的 token → `active=false`**；垃圾串 → `active=false`。RAG 侧据此返回 **401「登录已失效，请重新登录」**（同一 token 在改密码/封号前是放行的）。health：`revocation.enabled=true, policy=enforced, max_delay_seconds=30, fail_mode=closed, revoked=1` |
| **nginx 鉴权模式** | `RAG_AUTH_MODE=jwt`；两侧 JWT 密钥同值且长度合规；RAG 只监听回环；`/api/internal/` 公网 404；公开路径只剩 `/rag/api/health`（监控需要，按设计）。**公网匿名调用问答接口 → 401** |
| **API 错误格式** | 经 nginx 实测四个都是 JSON：不存在路径 → 404、方法不对 → 405、请求体非 JSON → 400、未登录 → 401，均带 `code`/`msg`/`message`/`data`/`request_id`（不再是 Flask 的 HTML 页） |

## 三、过程中发现并修掉的部署缺陷

四条共同的形状：**本机与 CI 都看不出来，而后果是"部署看起来成功了，其实没生效"**。详见 `deploy/README.md` 第九节（含复现命令与排查提示）。

| # | 缺陷 | 性质 | 修法 |
| --- | --- | --- | --- |
| 1 | **CRLF 让服务器上的 shell 脚本一行都跑不了**：229 个文本文件带 CR，含鉴权门禁脚本与 nginx 站点配置 | 上传路径缺陷（本机 `core.autocrlf=true`）+ 上一轮我加的"代码同步排除规则"未覆盖它 | 仓库根 `.gitattributes`（`* text=auto eol=lf`）+ 上传脚本对必须为 LF 的文件就地转换并打印；工作区已刷成全 LF |
| 2 | **`RAG/data/` 里住着被跟踪的源码**，而上传把它当数据目录整体排除 → 服务器上新 `runtime.py` 配旧 `chroma_store.py`，`ImportError: cannot import name 'ChromaClients'`，RAG 反复重启 | 上一轮我改的排除规则覆盖面不足（该目录同时住着 400 MB 制品与 20 个 `.py` 源码） | 上传脚本新增一步：单独同步 `git ls-files RAG/data backend/data` 列出的文件（大制品都未被跟踪，这个列表恰好是"小而必需"的部分） |
| 3 | **统一 lock 在 Linux 上装不上**：`uvloop>=0.15.1` 未固定版本 → `--require-hashes` 拒绝；根因是锁由 Windows 生成、`uvicorn[standard]` 被 `--strip-extras` 剥掉 extras、Linux 专有包不在 Windows freeze 里 | 上一轮我引入（`requirements.lock` 与"优先用锁"的部署改动），且本机验证"锁可重装"恰好因平台差异而漏过 | `01_setup_server.sh` 默认改回 `requirements.txt`，锁需显式 `USE_UNIFIED_LOCK=1`；**生成器平台完整性 + CI 在 Linux 上真装一遍仍待做**（见第四节） |
| 4 | **`install_services.sh` 单元名缺 `.service`** → 在 2/5 步必然中止（`die "缺少 …/systemd/china-war-backend"`） | 仓库里早有的缺陷（非本轮引入），`bash -n` 查不出来、CI 也从没跑过该脚本 | 补全后缀；`scripts/check_deploy_config.py` 新增守卫：解析脚本里的单元名并逐个断言对应文件存在（已实测：用 HEAD 的坏版本报 3 项失败） |

另有一处非缺陷但值得记的坑：**`pkill -f "env-switch.sh"` 会把自己那条 ssh 命令行也匹配上并杀掉**（远端 shell 的命令行里就含这个字符串），表现为"命令无任何输出"——用中括号技巧（`env-swi[t]ch`）避开自匹配。
