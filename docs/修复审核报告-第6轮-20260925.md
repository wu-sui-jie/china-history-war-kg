## 一、验收结论

**两项新功能本体质量是六轮里最好的，但各存在必须修的漏洞。**

- 用户管理页：`@require_admin` 实时查库 fail-closed、不能改自己、角色白名单、菜单三级裁剪三方（后端/白名单/路由）同口径——**未发现 editor/viewer 可利用的提权路径**；
- 问答隔离：桥（只解析转交）与 store（独占换桶）职责清晰，origin 校验正确，换桶顺序有装配级测试与浏览器 e2e 钉住；
- 但隔离功能的**两条核心保证在边界路径上被打破**（前端 H1 登出泄桶、RAG H1 legacy 收编），且**测试门禁漏掉了它们**（CI 只跑 component、后端零常驻测试）——这正是四路审查里价值最高的发现。

## 二、必须修复（高危，4 项）

### H1（前端·隔离漏洞）登出/会话过期时，当前账号的完整问答历史被写进全局共享 key

- 链路：`inference/index.vue:970-979` 的 `onBeforeUnmount` **无条件** `saveChatHistory()`；而 `BasicLayout.vue:183-187` 的 `logOut()` **先** `clearSession()`（userInfo 置空）**再**跳登录。卸载 flush 时 `userInfo.id` 已是 `undefined`，key 退回全局 `chatHistory`—— outgoing 用户的**全部**会话被复制进公共桶，任何后续账号都能读到。token 过期自动跳登录同样触发。
- 修法（改动很小）：flush 前捕获 uid（setup 期缓存），或 `userInfo?.id` 为空时跳过写入；深 watch 防抖保存同批覆盖。补一条"登出时不落盘/落对桶"的页面级用例（现有测试恰好全是单侧单测，盲区正在此处）。

### H2（RAG·隔离漏洞）legacy 回落把旧全局记录"收编"进先到者的账号桶

- `RAG/frontend/src/stores/session.ts:423` 的 `readPersisted()` 会回落 `LEGACY_STORAGE_KEYS`（全局 `ragv5-session-v2/v1`）；uid 桶为空的新登录者会读到全局旧数据并最终写进自己的桶。升级前用过 RAG 的账号 A 的记录，会被升级后第一个登录的账号 B 收编——与主应用侧"老全局记录归档、不归属任何账号"（`userScopedStorage.ts:9-12`）的策略直接矛盾；隔离损坏数据时还会 `removeItem` 删全局共享原值。
- 修法：**uid 非空时只读账号桶**，legacy 回落仅限无 uid（独立访问 :8000）场景；补"uid 桶 + 预置 legacy 数据"用例（现有 93 例恰好没这条组合）。

### H3（CI 门禁）主前端 CI 漏掉整个 tests/unit 目录

- `ci.yml:210` 只跑 `pnpm run test:component`（= `vitest run tests/component`）。本轮新增的 `router-guard`（守卫分级 12 例）、`user-scoped-storage`（隔离存储 8 例）与既有 `inference-render`、`knowledge` 测试**都不在门禁内**，只在实施者本机跑过。
- 修法：package.json 补 `test:unit` script，CI 加跑；或直接改跑 `pnpm test`。

### H4（后端门禁）"22 项验证"不可复现，backend 零常驻测试

- 实施记录声称"真实 SQLite + test_client 22 项全通过"，但 backend 下没有任何测试文件（脚本跑完即删）——admin 接口防呆、菜单三级裁剪、提权链路在 CI 里只有 compileall + ruff 兜底。这是**第二次**出现该模式（第 5 轮的 20 项 API 回归同样一次性）。
- 修法：把 admin 接口 + 菜单裁剪 + 提权链路写成常驻 pytest（打桩 Neo4j 即可，不需要真实库），挂进 legacy-backend job。
