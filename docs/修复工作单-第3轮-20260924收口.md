## S1 安全与部署（人工执行，公网上线前阻塞）

- [ ] **S1-1【最紧急，五分钟】轮换历史泄露的凭据（R2-1）**
  - 现状：连续三轮未执行，`backend/.env` 仍含历史口令（实测 grep 命中）；初始提交 57eea5b 的 Neo4j 密码与 JWT 密钥在公开仓库历史仍可取回。
  - 步骤：① Neo4j `ALTER USER neo4j SET PASSWORD '<新口令>'`；② 更新 `backend/.env` 的 `NEO4J_PASSWORD`；③ `openssl rand -base64 48` 生成新 `JWT_SECRET` 写入 `.env`（旧 token 立即失效）；④ 验证旧后端能连 Neo4j、登录正常。步骤文档：`deploy/README.md` 第六节第 7 条。
  - **决策项**：是否用 `git filter-repo` 重写历史彻底清除旧凭据（会改写全部提交哈希、需强推、所有协作者重新 clone）——不做则轮换后的旧凭据仅对「当前 HEAD 之后」无效。
- [ ] **S1-2【部署时必做】启用 RAG 反代层鉴权（RAG-1）**
  - 现状：`deploy/nginx/china-war.conf:88-89` 的 `auth_basic` 仍是注释；`/api/query` 公开、仅进程内限流（多实例即失效）。
  - 做法：公网部署时取消注释 `auth_basic` 两行 + `htpasswd` 建口令文件；同时把 `CORS_ALLOW_ORIGINS` 改为实际域名。局域网/本机部署可暂缓但需在部署记录中标注。
