## 严重度定义

| 级别 | 含义 |
| --- | --- |
| 高 | 安全可被利用 / 数据损坏或不一致 / 可复现的功能性 bug / 影响学术结论 |
| 中 | 正确性风险 / 部署陷阱 / 可维护性严重受损 |
| 低 | 仓库卫生 / 可移植性 / 风格不一致 |

## 总体结论

项目整体处于**「能演示、文档好，但安全基线缺失、并发正确性不过关」**的状态。四个模块成熟度差异极大：

- **RAG**：经多轮系统性自审整改，工程化水准显著高于平均（SSE 生命周期、数据版本化、266 个测试、供应链防护），问题集中在公网部署缺口；
- **backend**：典型的「能跑但不可运维」——Cypher 注入、全局身份串号、双写吞异常、3712 行巨石文件、无依赖声明；
- **frontend**：鉴权层「看起来有、实际没有」，mockjs 进生产包且是菜单唯一数据源，另有一处可复现的 404 死链；
- **entity-event-relation**：工程意识不错，但存在空结果污染缓存、评估 recall 公式错误（影响学术结论）等正确性问题。

**最紧迫三件事**：① 轮换 git 历史中已泄露的 Neo4j 密码与 JWT 密钥；② 修复 backend 的 Cypher 注入与并发身份串号；③ 修复前端鉴权空转与 XSS 组合，在此之前不宜对外部署。
