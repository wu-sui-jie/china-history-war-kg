**阶段 5：全书评估口径（阶段 2.6 / 2.7 已走完，这条现在可以接着做）**

**先分清要哪个量**——两个量的可行性完全不同：

| 要的量 | 回答的问题 | 需要什么 | 全书可行吗 |
| --- | --- | --- | --- |
| **精确率** | 导进库的这批记录**有多少是对的** | 只需抽样看**预测**，不需要"原文里一共有哪些" | ✅ 可行、便宜、一个晚上级 |
| **召回率 / F1** | 还**漏了多少** | 必须知道"原文里该有哪些"→ 覆盖式的答案 | ✅ 可行，但按周计 |

**为什么现在测不了"全书"**：参考集只覆盖三个朝代块（明/唐/秦汉）= 全书 **31.7%** 的字符；
其余 68.3% **没有答案**。拿全书产物去对这份答案，72% 的预测没有可比对象 → 那个数（宏观 26.9%）
不是"抽得差"，是**没有可比对象**。所以"整体评估"当前做不了，**不是路径选择问题，是没有答案**。
（同一个产物、同一份参考集，只挪 dev/test 边界，宏观 F1 就从 26.93% 跳到 44.46%——错配的代价。）

**三条路**：

1. **抽样人工判定（推荐先做）**：`sample_for_review.py --total 350~600 --seed <固定>`
   从**产物**里按层（事件/实体/关系）+ 事件按朝代**分层随机**抽，样本天然覆盖全书；
   `expand_review_context.py` 换成原文上下文 → 人逐条判 对/错/无法判断 + 判据 →
   `summarize_review.py` 出**精确率 + Wilson 区间**。**这条路已经走了两轮**（同方法、350 条、同种子）：
   旧产物 82.8%（区间 [78.4%, 86.5%]、"无法判断" 6.9%）→ 新产物 **91.43%**
   （区间 [88.03%, 93.93%]、"无法判断" 0 条），**区间不重叠 → 改善成立**。**它答不出召回率**。
2. **抽样标注 gold（要 P/R/F1 时做）**：**评估不需要全书覆盖，只需要有代表性的样本**——
   从 211 段里分层随机抽 **40~50 段**标成 gold，得到全书 P/R/F1 的**估计 + 区间**（可外推；
   现有的三个块是"为试点而选的连续块"，不能外推）。成本约 **6,400~8,000 行判定**（按三个块
   11,044 行 / 97,279 字符折算），加 20% 双标 → **按周计**。**不要做全书全覆盖**：那是 3.15 倍
   （约 3.5 万行判定、按月起），而多买的只是"没有抽样误差"这一项，标注自身噪声可能更大。
   注意这套流程要**跟着走**（草稿 → 人工逐条判 → 20% 双标 → 仲裁），否则新标的部分会重蹈旧 gold
   的覆辙（多模型汇总、字段没人工处理）。草稿表是机器生成的，这一步免费。
3. **给产物加字符坐标（工程放大器）**：pipeline 分段时本来就算过 `source_offset`，只是没写进产物。
   加上之后**评任何子集都不必再跑子集**（省掉每次 171 次调用），路 2 里抽中的段也能直接切出来评。
   它**不解决"没有答案"**，只解决"范围对齐"。

**明确排除**：让模型当裁判——本项目的参考集重建起因就是拒绝"模型对模型"（那正是旧 gold 的毛病）；
体检那 17 项只测"合不合理"（悬空边、枚举合法性、证据率…），是红线，不能当准确率上报。

**建议顺序**：①抽样判定（"这版数据有多少是对的"）——**已完成两轮** → ③给产物加字符坐标
（一次性，以后评任何子集都不必再跑子集）→ 需要 P/R/F1 时再做 ②抽样标注 gold（20~30 段，按周计）。
三条互不阻塞，可分批。
