entity-event-relation 项目说明

基于大语言模型的历史战争文本知识抽取与评估系统。
通过三轮递进式提示工程，从非结构化战争史文献中自动构建结构化知识图谱，并提供与人工标注数据对比的学术级评估体系。
一、项目简介

    本项目面向中国战争史文献，实现以下核心功能：
    
    实体抽取：识别地点（含古今地名映射）、组织（国家/军队/联盟）、人物（官职/角色/归属）。
    
    事件抽取：判定事件类型 → 抽取子事件（生命周期阶段） → 补全 14 维事件要素。
    
    关系抽取：构建事件与地点、组织、人物，以及事件与事件之间的四类关系网络。
    
    智能长文本处理：自动切分文本（默认 1800 字符/段，保留 200 字符重叠），合并多段结果。
    
    缓存机制：基于文本 MD5 的 API 调用缓存，避免重复付费。
    
    学术评估：基于模糊匹配的最优评估策略（evaluate.py），输出 P/R/F1 及宏观平均 F1。

二、核心特性

    三轮智能抽取
    实体层：地点、组织、人物，字段完整（含现代名、朝代、角色等）。
    
    事件层：
    
        Q1：12 种战争事件类型判定（如"统一战争"、"农民起义"）。
        
        Q2：细粒度子事件抽取（时间 + 生命周期阶段）。
        
        Q3：14 维完整事件要素（名称、时间、地点、参战方、结果、影响等）。
    
    关系层：
    
        事件-地点（10 种，如主战场、出发地）
        
        事件-组织（8 种，如发起方、防守方）
        
        事件-人物（11 种，如统帅、谋士、君主）
        
        事件-事件（5 种，如因果、顺承）
    
    长文本自适应

        智能切分（优先句子边界）
        
        结果合并与去重（实体按名称去重，事件按名称去重，关系按三元组去重）
    
    缓存管理

        基于文本 MD5 哈希缓存 API 结果
        
        分段级缓存支持，大幅降低 API 费用
    
    最优评估策略（evaluate.py）
        事件名称模糊匹配：融合字符匹配、包含关系、fuzzywuzzy算法（阈值50%）
        
        事件中心评估：严格匹配事件，只保留匹配事件中的实体，确保事件 F1 高准确率
        
        实体中心评估：宽松过滤实体，保留所有可能与标注匹配的实体，确保实体 F1 高召回率
        
        关系类型归一化：将"主战场"→"发生地点"，"统帅"→"指挥"等
        
        关系尾实体模糊匹配：阈值70%，支持"涿鹿"≈"涿鹿县"等变体
        
        综合结果：输出实体F1、事件F1、关系F1、宏观平均F1

四、快速开始

    1. 安装依赖
        pip install openai&gt;=1.0.0 pydantic&gt;=2.0.0 python-dotenv&gt;=1.0.0 jinja2&gt;=3.1.0 tqdm&gt;=4.65.0 fuzzywuzzy python-Levenshtein pandas openpyxl

    2. 配置 API 密钥
        密钥通过系统环境变量 Chinese_txt 提供（不要在代码中硬编码密钥），
        也可在 config/.env 中设置（该文件已被 git 忽略）：
            Chinese_txt=sk-xxx
            DEEPSEEK_MODEL=deepseek-chat
            API_BASE_URL=https://api.deepseek.com/v1

    3. 准备数据
        待抽取文本置于 data/ 目录（如 data/中国历代战争简史.txt）
        
        如需评估，在 data/annotations/ 下准备对应的 JSON 标注文件（实体、事件、关系）

    4. 运行抽取
        python main.py data/中国历代战争简史.txt
        选项：
        --no-split：禁用长文本分段
        
        --no-cache：强制刷新缓存
        
        抽取结果将保存至 output/中国历代战争简史/，包含 9 个 JSON 文件和 Excel 文件。

    5. 运行评估
        python evaluate.py
        
        评估结果保存至 evaluation/optimal/results.json

五、评估策略详解（evaluate.py）

    评估指标说明（P/R/F1）
        在信息抽取领域，使用以下三个标准指标衡量抽取质量：
        
        ┌─────────┬──────────┬─────────────────────────────┬────────────────────┐
        │  指标   │  全称    │           含义              │       公式         │
        ├─────────┼──────────┼─────────────────────────────┼────────────────────┤
        │    P    │ Precision│ 精确率：预测正确的比例      │ TP / (TP + FP)     │
        │         │ （精确率）│ → 模型预测的结果中，多少是对的                     │
        ├─────────┼──────────┼─────────────────────────────┼────────────────────┤
        │    R    │ Recall   │ 召回率：标注被找回的比例    │ TP / (TP + FN)     │
        │         │ （召回率）│ → 人工标注的内容中，多少被模型找回来了             │
        ├─────────┼──────────┼─────────────────────────────┼────────────────────┤
        │   F1    │ F1-Score │ 综合指标：P和R的调和平均    │ 2×P×R / (P+R)      │
        │         │          │ → 平衡精确率和召回率的综合评分                   │
        └─────────┴──────────┴─────────────────────────────┴────────────────────┘
        
        其中：
        - TP（True Positive，真正例）：预测正确且确实存在的数量
        - FP（False Positive，假正例）：预测了但实际不存在的数量（误报）
        - FN（False Negative，假负例）：实际存在但没预测出来的数量（漏报）
        
        举例（事件抽取）：
        - 人工标注了 10 个战争事件
        - 模型预测了 12 个事件
        - 其中 8 个预测正确（TP），4 个预测错误（FP），漏了 2 个（FN）
        
        则：P = 8/12 = 66.7%，R = 8/10 = 80%，F1 = 72.7%

    核心算法
        事件名称相似度计算：
            - 完全匹配 → 1.0
            - 标准化后匹配（去"之战"/"战争"/"起义"） → 0.95
            - 包含关系 → 0.9
            - 字符交集 + fuzzywuzzy（ratio/partial_ratio/token_set_ratio）→ [0,1]
            - 阈值：≥0.5 视为候选匹配
        
        贪心最优匹配：
            按相似度降序排序，依次匹配，确保每个标注事件只匹配一次预测事件
        
        事件映射表：{预测事件名: 标注事件名}

    评估流程
        步骤1：构建事件名称映射（预测↔标注）
        
        步骤2：实体评估（事件中心过滤）
            - 从匹配事件的事件要素中提取相关实体（Place, Person, Aggressor, Defender）
            - 过滤预测实体：只保留与事件实体或标注实体模糊匹配（≥70%）的
            - 严格名称匹配计算 P/R/F1
        
        步骤3：事件评估
            - 基于事件映射表计算 TP/FP/FN
            - TP：映射到的标注事件数
            - FP：未匹配的预测事件数
            - FN：未匹配的标注事件数
        
        步骤4：关系评估
            - 只评估与匹配事件相关的关系
            - 关系类型归一化（如"主战场"→"发生地点"）
            - 尾实体模糊匹配（阈值70%）
            - 构建三元组 (head, relation, tail) 计算 P/R/F1
        
        步骤5：综合结果
            - 实体 F1 = 实体中心评估的实体 F1
            - 事件 F1 = 事件中心评估的事件 F1
            - 关系 F1 = 关系评估的关系 F1
            - 宏观平均 F1 = (实体F1 + 事件F1 + 关系F1) / 3

    评估输出
        保存综合结果到 evaluation/optimal/results.json
        
        控制台输出：
            事件匹配: 预测X, 标注Y, 匹配Z (匹配率)
            实体: P=XX%, R=XX%, F1=XX%
            事件: P=XX%, R=XX%, F1=XX%
            关系: P=XX%, R=XX%, F1=XX%
            【最终评估结果】
            实体抽取 F1: XX%
            事件抽取 F1: XX%
            关系抽取 F1: XX%
            宏观平均 F1: XX%
