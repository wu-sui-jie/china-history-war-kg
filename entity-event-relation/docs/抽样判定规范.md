# 抽样判定规范（B 组人工核验）

> **这份规范解决什么**：350 条抽样记录要由人判"对 / 错 / 无法判断"，判出来的数字是
> **抽样精确率**——它是这个项目里唯一不依赖那份不可信参考集的质量指标，也是阶段三
> E1（事件字段）、E2（关系）、E3（实体）三节的共同输入。
>
> **为什么必须先有规范**：判的人不止一个、判的时间也不止一次。没有统一口径，
> "对"的含义会随人随时漂（有人按"事实对就行"判、有人按"措辞也要对"判），
> 那么算出来的精确率与置信区间再漂亮也不可比。**这一页就是为了让不同人判出同一批数。**
>
> **已经用它走了两轮（2026-09-27 补）**：旧产物（`sample_20260926*`）精确率 **82.8%**
> （区间 [78.4%, 86.5%]、"无法判断" 6.9%）→ 换代后新产物（`sample_20260927*`）**91.43%**
> （区间 [88.03%, 93.93%]、"无法判断" 0 条）。两轮同方法（350 条、同分层、同种子 `20260926`），
> **区间不重叠 → 改善成立**。汇总脚本 `tools/summarize_review.py` 已就位。
> **再抽一轮就照这份规范做**；下一轮最值得盯的是最弱的那层（`关系:事件-事件`，本轮 57.1%）。

## 1. 用哪份表

| 文件 | 用途 |
| --- | --- |
| **`evaluation/review/sample_<批次>_with_source.csv`** | **要填的就是这份**（第二批是 `sample_20260927_with_source.csv`；第一批 `sample_20260926_with_source.csv` 已判完留档）。在 `判定（对/错/无法判断）`、`判据`、`备注` 三列上填 |
| `evaluation/review/sample_<批次>_with_source.json` | 同内容的结构化版本，供脚本汇总；不用管 |
| `evaluation/review/sample_<批次>.csv` / `.json` | **冻结基准，不要改**。跨版本对比靠它；判定结果会用 `定位键` 映射回这批定位 |

后一份表由 `tools/expand_review_context.py` 从冻结基准生成：`定位键` 与 `记录摘要` 逐行照抄，
只把上下文从"模型给的证据（截断 400 字）"换成"**原文**里那一段（定位点前 900 字、后 200 字）"，
并把模型给的证据单独放进一列。第一批（2026-09-26）350 行**全部**给出了原文上下文，
按可靠程度分四档（**下面是那一批的实测分布，换一批会变**）：

| 定位方式 | 行数 | 意味着 |
| --- | ---: | --- |
| `记录证据` | 283 | 上下文确实覆盖这条记录的证据，可直接判 |
| `记录证据（部分：…）` | 11 | 证据是**多段原文拼起来的**，上下文只覆盖其中一段——判之前要自己补看 |
| `所属事件证据` | 31 | 关系的证据是模型改写的句子（原文里没有），改用它所属事件的原始证据定位 |
| `名称定位` | 25 | 只按人名/事件名找到的，**很可能不是这条记录对应的那一段**，必须自己核对 |

### 列的含义

| 列 | 是什么 | 你要做什么 |
| --- | --- | --- |
| `分层` | 抽样用的层（`实体:地点`、`事件:东汉`、`关系:事件-人物`…） | 不用管，只用来筛选 |
| `定位键` | 这条记录的身份（见下） | 不用管 |
| `记录摘要` | **产物抽出来的记录**，一行里有它的全部字段 | **读它**——被判断的对象 |
| `原文上下文` | **原文**里定位到的段落（含前后段），`〈 〉` 标出产物证据在原文里的对应位置 | **读它**——判断的依据 |
| `产物证据` | **模型自己写的**证据（事件是 `source_text`，关系是 `evidence`），一字未改 | 读它——"证据支不支持这条记录"也是判断的一部分 |
| `定位方式` | 上下文是怎么定位到的（`记录证据` / `记录证据（部分…）` / `所属事件证据` / `名称定位`） | **先看这一列**：只有 `记录证据` 可以直接判；其余三档都必须自己核对上下文是不是这条记录的原文 |
| `原文出处` | 证据在全书里的字符区间，便于去原文里跳转 | 需要回原文时用 |
| `判定（对/错/无法判断）` | 空 | **填** |
| `判据` | 空 | **填**，格式见 §3 |
| `备注` | 空 | 表本身有问题（抽错层、上下文不够）写这里 |

`定位键` 长这样：`event|崤底|东汉|27年|崤底`（事件｜归一名称｜朝代｜起始时间｜首个地点）、
`entity:person|余善|西汉`、`event_person_relations|二破江南大营|统帅|李世贤`。
名字被归一化（`崤底之战`→`崤底`）、地点被截断（`东突厥（今内蒙古`），都是机器口径，不用人判。

## 2. 判什么、不判什么

- **只判**：抽到的**这条记录本身**按原文成不成立。
- **不判**：原文里该有而没抽到的（漏项）。精确率只测"抽出来的对不对"，
  "漏了什么"必须有参考集才知道——那是 C 组重建之后的事。
- **不要**因为"这条不重要""这条和别的条目重复"就判错。**重要性不是判据**，
  重复要去 `备注` 里写（那是抽样的观察，不是这条记录的对错）。

---

## 3. 三档，以及判据怎么写

**只有三档：对 / 错 / 无法判断。没有"部分对"。** 一条事件记录的摘要里有五个字段，
只要有一个写错，整条就填"错"——错在哪一项全部写在 `判据` 里。

判据用**固定的前缀**开头，后面接一句"原文写的是什么"。固定前缀是为了后面能机器汇总
（E1 要靠它把错误分成"漏抽 / 抽错 / 口径不同"三类）：

| 前缀 | 什么时候用 | 写法示例 |
| --- | --- | --- |
| `事件本身：` | 这条根本不该被当成事件收进来 | `事件本身：原文说的是"蒙金战争"这类概括，不是具体战役` |
| `时间：` | 年份缺失、写错、或与原文不符 | `时间：原文未给年份`、`时间：原文为建武三年（公元27年），一致` |
| `地点：` | 地点写错或指到别处 | `地点：原文作"崤底（即崤山）"，产物写"崤底、崤山"，同一处` |
| `主动方：` / `防守方：` | 攻守方向写错、或写成了另一方 | `主动方：原文是"商"（国），产物写"商汤"（君主），同一方` |
| `结果：` | 胜负写错、或原文没写结果 | `结果：原文只写"溃败"，产物写"大败并迫降8万余人"，一致` |
| `关系类型：` | 关系名与原文不符（统帅↔参战方这类） | `关系类型：原文里李世贤只负责虚攻湖州，统帅应为李秀成` |
| `关系方向：` | 事件-事件关系的 A→B 与原文时序相反 | `关系方向：证据说"统一南方后转兵北上讨伐北汉"，与 A→B 相反` |
| `实体类型：` | 人/组织/地点判错类 | `实体类型：原文里"鬼方"是部族，产物归到了地点` |
| `附属性字段：` | 角色、组织类型、现代名这类 | `附属性字段：组织类型写"部落"，原文是"方国"` |
| `上下文不足：` | 填"无法判断"时的理由 | `上下文不足：产物证据是改写句，未能定位到原文` |

判"错"时**必须回原文写出原文的说法**（"原文写的是什么"），只写"错了"后面没法用。

## 4. 逐层判什么

| 层 | 摘要里有什么 | 判什么 |
| --- | --- | --- |
| `实体:地点` | 地名 + 现代名 + 朝代 | 这个地名在原文里成立吗？被当成**地点**对吗？现代名指到了别处吗？ |
| `实体:人物` | 人名 + 角色 + 朝代 + 所属组织 | 这个人存在吗？**角色**（君主/统帅/将领/谋士…）与组织归属对吗？ |
| `实体:组织` | 组织名 + 类型 + 朝代 | 这个组织成立吗？**类型**（国家/部落/军队…）对吗 |
| `事件:*` | 事件名 + 朝代 + 起始时间 + 地点 + 主动方 + 结果 | ①**该不该被当成一个事件收进来**；②时间、地点、主动方、结果逐项对不对 |
| `关系:事件-人物` | 事件 —[关系名]→ 人名 | 在这段原文里，这个人和这场战事的关系**是不是这个类型** |
| `关系:事件-地点` | 事件 —[关系名]→ 地点 | 该地点在这场战事里的角色（主战场/次要战场/出发地…）对不对 |
| `关系:事件-组织` | 事件 —[关系名]→ 组织 | 这个组织在这段原文里是参战方、同盟方，还是只是旁观 |
| `关系:事件-事件` | 事件 A —[关系名]→ 事件 B | **方向**对不对（顺承 A→B 表示 A 先发生）、类型对不对（因果/并列/包含） |

**"该不该被当成事件收进来"的口径**（整改方案 10.1 第 1 项）：
像"蒙金战争"这种过宽的概括**不算**一个事件，像"三峰山之战"这种具体战役**算**；
迁都、会盟这类非军事事件**不算**（本系统是战争数据系统）。

## 5. 逐字段规则（最容易判不一致的地方）

### 时间

1. **先看给的上下文，没有就回原文查**（原文：`data/中国历代战争简史.txt`）。
   事件的时间常写在**前一段**，而 `产物证据` 那一列往往只有过程描述——这正是上下文要扩到
   "含前段"的原因。
2. **写法不同但指同一年算对**：原文写"建武三年"、产物写"27年"，是换算不是错；
   原文写"公元前1046年"、产物写"前1046年"同理。项目评估器对 `StartDate` 的口径是
   "两侧都能解析出年份、相差不超过 1 年算对"，人工判可以直接对齐它。
3. **原文确实没写、产物却填了具体年份 → 判错**（`时间：原文未给年份`）。
   前提是**回原文确认过真的没写**——只凭给的那一段没有就判错，会冤枉产物。
4. **回原文也查不清**（叙述跨年、指哪一场有歧义）→ `无法判断`，判据 `上下文不足：时间无法定位`。

### 地点

- 原文"崤底（即崤山）"、产物写"崤底、崤山"算**对**（同一处，产物列了别名）。
- 产物列了多个地点、其中一个是别的战役的 → 判**错**（`地点：混入了原文另一场战役的战场`）。

### 主动方 / 防守方

- **同一个战事方的不同粒度写法算对**：原文"商"（国）与产物"商汤"（君主）、
  原文"吴国"与产物"吴军"、原文"蜀"与产物"蜀汉"，都算对。
  **但判据里要写明** `主动方：原文是"商"，产物写"商汤"，同一方`——评估器按名称集合交集判，
  这类会被算成错，正是要量化的一类（E1 第 ③ 类"口径不同"的主要形态）。
- 攻守**互换**（把防守方写成主动方）→ 判**错**。
- 原文写"冯异军大败赤眉军"而产物把主动方写成赤眉军 → 判**错**。

### 结果

- 原文给了更多细节、产物写得更简（"大败宋军" vs "宋军大败"）→ 算**对**，没写错。
- 产物写的结果与原文**相反**（胜负颠倒）→ 判**错**。
- 原文没写结果、产物写了 → 判**错**（`结果：原文未给结果`）。

### 关系

- 判断依据是 `产物证据` + `原文上下文` 两列：证据句要能支持这条关系。
  句子里出现"议和"但那个组织只是旁观 → 判**错**（`关系类型：原文里该方只是旁观`）。
- 事件-事件的**方向**按时间判：`顺承 A→B` 要求 A 先发生；与原文时序相反 → `关系方向：` 判错。

### 实体属性

- 角色/组织类型**明显不符**（把文官写成统帅、把方国写成部落）→ 判错。
- **措辞差异算对**："统帅"与"主将"、"国家"与"政权"这类同义表述不判错。
- 现代名（地点）：指到了别处的判错；少写"县"这类后缀不判错。

---

## 6. "无法判断"什么时候用

适用：① `定位方式` 不是 `记录证据`，且核对后上下文确实不是这条记录的那一段，
自己回原文也没查出结果；② 上下文与产物证据都读完了，仍不足以核对摘要所写的内容；
③ 原文本身含糊或前后矛盾。

**不要用它逃避判断。** "无法判断"的比例本身就是个要报出去的数——它反映
"有多少记录连回原文都核不清"，是参考集完整度 `c` 的输入之一。判不准的时候，
在 `备注` 里写清卡在哪（缺哪一段、哪个信息），那对改进抽样表更有用。

## 7. 判例（都是表里的真实行）

**① 实体行 · 对** —— `人物 余善（角色 君主，朝代 西汉，组织 东越）`
> 原文：东越王余善反汉，自立为武帝。
> 判：**对** ｜ 判据：`角色/组织：原文"东越王余善"，君主、东越均一致`

**② 事件行 · 对（时间在上一段，证据段里没有）** —— `事件 崤底之战（东汉 27年，地点 崤底、崤山，主动方 冯异军，结果 冯异军大败赤眉军，迫降8万余人）`
> 产物证据段通篇没有年份；上下文里能看到上一段写着"公元27年，邓禹率领车将军邓弘等由河西回到湖县"。
> 判：**对** ｜ 判据：`时间：原文上一段"公元27年"，一致；地点"崤底（即崤山）"、主动方"冯异约赤眉会战"、结果"迫降赤眉军8万余人"均一致`
> **这一条说明了为什么必须用扩过上下文的那份表。**

**③ 关系行 · 错（证据与摘要自相矛盾）** —— `北宋灭北汉之战 —[顺承关系]→ 北宋灭南唐之战`
> 产物证据：`北宋统一南方诸割据政权后，即转兵北上，讨伐北汉。` + 重复一遍的同一句
> 判：**错** ｜ 判据：`关系方向：证据说"统一南方后转兵北上讨伐北汉"，即先南唐、后北汉，与 A→B 相反；且证据句整段重复`
> **方向类错误常常只看证据列就能判出来，不必回原文**——这也是"产物证据"单独留一列的价值。

**④ 事件行 · 错（字段与原文不符）** —— `事件 辽西渔阳之战（西汉 前128年，地点 辽西、渔阳，主动方 匈奴，结果 匈奴获胜，汉军损失殆尽，后燕兵救援，匈奴退去）`
> 原文：`次年秋，匈奴2万骑袭掠辽西（治所辽宁义县西），杀太守，虏去2千余人；接着击败渔阳太守千余人，进围韩安国营。汉军损失殆尽，得燕兵救援，匈奴乃退去。`
> 判：**错** ｜ 判据：`结果：原文作"得燕兵救援"，产物写"后燕兵救援"——"后燕"是四世纪的政权，此处不该出现`
> **注意这里为什么算错**：时间、地点、主动方、胜负都对，只有结果字段里的一个政权名写错。
> 判定列没有"部分对"，所以整条填"错"——错在哪一项全靠判据说清。
> 这一条也说明为什么不许把 `原文上下文` 换成"模型给的证据"就开判：
> 只有对着原文，才看得出"燕兵"被写成了"后燕兵"。

**⑤ 名称定位行 · 先核对上下文** —— `刘裕北伐灭后秦 —[投降]→ 姚泓`
> `定位方式` 是 `名称定位（端名「姚泓」在原文出现 5 次，取首次出现，请核对）`，
> 上下文是首次出现"姚泓"的那一段，读下来讲的是刘裕伐后秦之前的准备与进军，
> 并不直接包含"姚泓投降"这一句。
> 处理：**按事件名/人名自己回原文搜**（在 `data/中国历代战争简史.txt` 里搜"姚泓"），
> 找到相关段落后再判；确实核不清就填 **无法判断**，判据 `上下文不足：名称定位到的是另一段`。
> 名称定位的 25 行、加"部分"那 11 行都要这样过一遍——
> **不要拿一段明显不相干的原文去判"错"。**

**⑥ 证据本身有毛病时，去 `备注` 记一句** —— `人物 骆甲（角色 统帅，朝代 西汉…）`
> `产物证据` 是 `乃利用秦的甲士李必、骆甲利用秦的甲士李必、骆甲，迅速组建一支新骑兵`
> ——**同一句在证据里重复了一遍**（这类重复、拼接、只对上一句的形态在产物里不少）。
> 判：字段能由原文支持就**按字段判对错**（这条的"秦的甲士骆甲"原文里有，实体成立）；
> 另在 `备注` 写 `证据句重复`。
> **证据形态有问题 ≠ 这条记录错**，但两类都要记下来——前者是 E2 关系的输入，后者是 E1 的。

## 8. 判完之后

1. **汇总**：按分层与整体算精确率、"无法判断"的比例，并附 **Wilson 置信区间**。
   350 条的样本量在 p=0.5 时约 ±5 个百分点；分层的条数更少，区间会更宽，**分层数字只能当相对比较**。

   ```bash
   python tools/summarize_review.py                     # 打印汇总（整体 / 分类 / 分层 / 错误类型）
   python tools/summarize_review.py --json <仓库外临时目录>/review.json
   ```

   口径（在工具里写死，别在别处另算一套）：精确率 = 对 /（对 + 错），**分母不含"无法判断"**，
   它的比例单独报；区间用 Wilson（分层只有 8 条时正态近似会给出超过 100% 的上限）；
   错误类型按上面 §3 的**固定前缀**统计，且**只统计判"错"的行**——这正是那些前缀存在的理由。
   分类那一级（`关系 / 事件 / 实体`）是"这类问题有多大"的读数，对应阶段三的 E2 / E3 / E1。
2. **跨版本复用**：重跑之后用
   `python tools/sample_for_review.py --compare evaluation/review/sample_20260926.json --pred <新产物.json>`
   对同一批定位重新定位——注意工具自己的提醒："**仍然存在"不等于"仍然正确"**，
   判定列要用新产物重新核一遍。
3. **比较两次的结论**：置信区间重叠就**不要**声称"变好了"（这是整改方案定的口径）。
4. **参考集完整度 `c` 要另做一次交叉核对**（整改方案 §2.6.2：`c ≈ a/(a+b)`，
   `a` = 正确且在参考集内、`b` = 正确但参考集外）。两侧的**匹配规则必须与指标一致**：
   事件用评估器的配对（名字模糊匹配 + 语义约束），实体用名称集合，关系用三元组匹配。
   **不要用"名字完全相同"当口径**——实测那样算出来的 `c` 会低一个量级
   （事件层 12.5% vs 按配对规则的 28.1%），把配对口径的差异误读成"参考集只覆盖了八分之一"。
