### 关于模型的实测结论（第一轮遗留项 P0-3 的补充，落地属第二轮）

用项目自己的密钥探测（2026-09-26）：

| 探测 | 结果 |
| --- | --- |
| `GET /models` | **只有两个**：`deepseek-flash`、`deepseek-v4-pro`（没有 `deepseek-chat`） |
| 请求 `deepseek-chat` | 成功，但响应 `model` 字段是 **`deepseek-flash`**；`prompt_tokens=8`、无 reasoning、内容正常 |
| 请求 `deepseek-flash`（默认） | 成功但**进入思考模式**：`prompt_tokens=34`、`reasoning_tokens=20`、**可见内容为空** |
| `deepseek-flash` + `thinking={"type":"disabled"}` | **`prompt_tokens=8`、无 reasoning、内容正常** —— 与现状逐项一致 |

**结论**：`deepseek-chat` 是**别名，服务端已把它路由到 `deepseek-flash`**，所以"能力落后"不成立；而**显式写 `deepseek-flash` 会默认开启思考模式**（温度失效、小 `max_tokens` 会拿不到内容）。**已定：用 flash + 关思考**，可做到零行为变化；换来三样好处——修好 P0-3 的自证说谎、零额外成本（缓存已因第一轮的提示词改动全废）、保住分阶段温度。**`deepseek-v4-pro` 不用**（实测它同样默认思考）；若将来要追能力，那是条件触发的第四轮。

| **P0-4** 语义约束过严且无证据 | 新增 `tools/event_pairing_review.py`：对照"开/关约束"两次配对，导出**被拆掉的配对**（含相似度、拒绝原因、两侧朝代/时间/地点字段）供人工判定。实跑后确认**约束确实过严**，成因是四处实现缺陷：① 同名事件没有豁免（144 对被拆里 22 对同名）；② 地点只比"首个有效地点"（`宁锦之战` 两侧是同一集合、顺序相反也被拒）；③ 朝代按字符串相等（`清`/`明`、`五代十国`/`后唐/后梁` 这类口径差异被拒）；④ 年份拿标注残值比（`153` vs `1900年6月`）。四条逐条修好，另补：多值地点按**集合**比、残缺年份不参与、朝代按**时代档位**判（相邻档位相容、认不出就放行） | 配对 **176 → 231 对**；被拆 **144 → 86 对**。人工判读 41 对（相似度 ≥0.7 的 27 对 + 中低 14 对）：剩下的拒绝绝大多数是**真错配**（`北京之战→英法联军攻占北京` 1900/1860、`东京陷落之战→天津陷落` 北宋/清、`李渊攻占长安之战→李自成攻占西安` 隋/明），少数是粒度差异（`宋魏战争→宋魏互伐`）。导出物：`evaluation/review/pairing_diff_*.csv/json` |
